# 00 · 接单与对稿（Intake & Alignment）

> 用户发来"一首歌 + 一句想法"，到这里只完成了 5%。
> **在动笔写第一个 note 之前，必须先完成三件事：彻底听懂、把听懂的东西翻译给用户、和用户对齐预期。**

这条流程存在的理由：谱面是主观艺术。你不问，做出来的就是"你的谱"，不是"主人想要的谱"。
但也不能什么都问——**能自己判断的，就别拿去占用用户的注意力**。

---

## 1. 素材清单

| 类型 | 必需 | 说明 / 缺失时的处理 |
|---|---|---|
| 音频 | ✅ | mp3 / wav / flac / ogg。采样率、时长先记录 |
| 制作想法 | ⭕ | 一句话也算。没有就说明"我全权发挥" |
| 歌词 | ⭕ | 有 → 对齐 + 语义分析；没有 → 用 ASR 或人声段落推断 |
| 曲绘 | ⭕ | 没有 → 生成或建议；注意 `aspectRatio` |
| 参考谱面 | ⭕ | 用户说"像某个谱"时，去社区下载那张来对照 |
| 禁止项 | ⭕ | 例如"不要用抖动""不要快""别做太难" |

> 素材不全不代表不能开工，**代表你要在 Brief 里把假设写清楚**。

---

## 2. 阶段 A · 彻底分析（不产出任何谱面代码）

按顺序执行，每一步都要落到纸面（`analysis.json` + 设计笔记）：

1. **客观层**：`tools/analyze_music.py` → BPM / offset / onset / 能量 / 结构 / 人声区段
2. **结构层**：把算法边界人工改写成有名字的段落表（Intro/Verse/Chorus/Bridge/Drop/Outro）
3. **歌词层**：时间轴、逐句语义、关键词、重复句、停顿
4. **情感层**：给每个段落打三个 0~1 的分值 → `张力 tension`、`明亮 brightness`、`密度 density`
5. **叙事层**：一句话概括"这首歌在讲什么"，以及"它想让听众经历什么样的情绪旅程"
6. **演奏层**：哪些瞬间是"必须打中的点"（鼓点、重音、歌词落字、静音前的最后一拍）

> 完整方法见 [`01-music-analysis.md`](01-music-analysis.md)（含歌词与情感专章）。

**门槛**：说不清"第 2:14 那一下为什么爽"，就还没分析完。

---

## 3. 阶段 B · 把分析翻译给用户（没有可视化工具时的描述法）

用户看不到你的分析图。你不能说"能量曲线在 78s 有一个峰"，要说**人话**：

| ❌ 不要 | ✅ 要 |
|---|---|
| "RMS 峰值为 0.0dB，位于 78.4s" | "1:18 副歌第一下鼓砸下来，整首歌最响的一刻" |
| "structure.boundaries 有 8 段" | "全曲可以分成 5 个情绪阶段：试探 → 铺陈 → 第一次爆发 → 抽离 → 总爆发" |
| "建议 moveY 使用 easing 4" | "判定线会像被人从下面顶了一下，弹起来再落回" |
| "NPS 峰值 11" | "最密的地方一秒要打 11 下，双手交替刚好，单手会累" |

**描述模板**：`时间点 + 听觉事实 + 画面动作 + 玩家体感`

> 例："2:05 人声最后一个字拖长，鼓全停了 —— 这里我打算让所有判定线在 1 拍内散开到屏幕边缘、只留主线，玩家会突然'空'一下，像失重。"

## 4. 阶段 C · 对稿提问协议

### 4.1 三条原则

1. **锚定到具体时间**：每个问题都带"第几分几秒 / 第几拍"，不要问抽象风格。
2. **给选项 + 代价**：每个选项都要说清"打起来什么感觉 + 制作上要付出什么"。
3. **一次 ≤ 4 个问题，并且给出默认答案**：用户可以直接说"都按你的默认来"。

### 4.2 提问模板

```
【第 X 段：0:45 - 1:10 · 蓄力段】
听觉事实：鼓点从 4 分音符加密到 8 分，人声开始上挑，弦乐铺底进来
我的默认方案：note 密度从 2.5 提到 4.5，判定线缓慢上移 + 轻微倾斜
需要你定的：
  A. 保守 —— 密度只到 3.5，保持干净（好读，冲击力稍弱）
  B. 我的默认 —— 4.5，渐强到副歌（推荐）
  C. 激进 —— 6.0，提前爆发（爽，但会削弱后面副歌的反差）
```

### 4.3 该问的四类问题

| 类别 | 问法示例 |
|---|---|
| **强度分配** | "全曲只有一次'顶点'，你希望放在 2:30 的最终副歌，还是 1:50 的第一次？" |
| **演奏取向** | "这首歌适合做'跟着唱'（Tap 多、留白多）还是'手指体操'（Drag/Flick 密集）？" |
| **叙事取舍** | "Bridge 那段几乎是静音，我可以做 8 秒零音符纯演出。接受吗？" |
| **风险/边界** | "这个高潮我想用 60+ 判定线 + 镜头震动，手机上可能掉帧。要不要降级？" |

### 4.4 不该问的问题

- ❌ "你想要什么风格？"（太空，用户答不出来）
- ❌ "难度定几级？"（应该由你根据音乐和密度给出建议值，让用户微调）
- ❌ 每写 10 个 note 就确认一次（打断心流）
- ❌ 让你自己就能查证的事实（BPM、时长、格式）

## 5. 阶段 D · 自由发挥清单（用户没说的，你负责）

这些不需要请示，**做错了也要做**，因为"没想法"比"想法不对"更糟：

| 项目 | 你该怎么做 |
|---|---|
| 判定线分组与命名 | 按叙事角色分：演奏 / 表演 / 纹理 / 文字 / UI |
| 演出轴线 | 给每个段落指定"视觉重心"（左/右/中/环绕） |
| 转场语言 | 段落交界必须有明确视觉事件（重组 / 散开 / 闪光 / 静止） |
| 色彩与亮度 | 跟随 `brightness` 分值与曲绘主色调 |
| 留白 | 静音段、长音、副歌前的半拍停顿 |
| 手感细节 | 重音给大 note、弱拍给小 note、滑音给 Flick |
| 收尾 | 最后一拍必须有"落地感"，不能突然结束 |
| 首屏 | 前 3 秒决定玩家要不要继续，必须有钩子 |

**自由度边界**：不违反 [`SKILL.md`](../../SKILL.md) 的硬规则 R1–R10，其余全部自由。

## 6. 阶段 E · 冻结剧本，开始施工

对齐完成后产出一份 **Art Direction Brief（一页纸）**，双方确认后再写谱：

```markdown
# 《曲名》Art Direction Brief

## 一句话
一首关于"从压抑到爆发"的歌，谱面要让玩家体验一次"被按住然后挣脱"。

## 段落剧本
| # | 时间 | 段落 | 情绪 | 张力 | 密度 | 视觉重心 | 关键事件 |
|---|---|---|---|---|---|---|---|
| 1 | 0:00-0:18 | Intro | 悬停 | 0.2 | 1.5 | 中 | 单线呼吸 |
| 2 | 0:18-0:52 | Verse | 克制 | 0.4 | 3.0 | 左右摇 | 线随贝斯摆 |
| 3 | 0:52-1:18 | Build | 蓄力 | 0.7 | 4.5 | 中上 | 线上移+加密 |
| 4 | 1:18-1:52 | Drop | 爆发 | 1.0 | 8.0 | 全屏 | 60 线炸开+shockwave |
| ... |

## 技术选型
- 判定线：主线 1 + 表演线 6 + 纹理线 12 + 文字线 0
- 特效：vignette（全曲）+ shockwave（Drop 首拍）+ glitch（转场）
- 难度：IN 14（峰值 NPS 8，含 2 处双押）

## 已知取舍
- 为保证手机性能，Drop 段不用 chromatic
- Bridge 保留 6 秒零音符
```

> 这份 Brief 一旦确认，就是施工图。中途想改，**先说"我要改剧本"**，不要偷偷改。

---

## 7. 阶段 F · 施工与回访

```
写谱 → tools/selfcheck.sh → 看联系表/视频 → 自查 → 修 → 再跑
```

每完成一个大段落（或全曲第一版），把**视觉产物**（联系表 PNG / 视频）交给用户看，同时给出：
- 这一段我做了什么
- 和 Brief 的偏差在哪、为什么
- 需要用户决定的 1~2 个点

**禁止**把"导入测试"甩给用户。导入前的验证见 [`docs/06-qc/02-visual-selfcheck.md`](../06-qc/02-visual-selfcheck.md)。

---

## 8. 反例

- ❌ 用户说"做首歌"，直接开始写 JSON → 做完发现方向完全不对
- ❌ 一口气问 12 个问题 → 用户放弃沟通，说"你随便"
- ❌ 只问"要不要加特效"，不问"哪里需要爆发"
- ❌ Brief 里只有"高级感""燃"这类形容词，没有一个时间点
- ❌ 用户说"自由发挥"，结果你真的什么都不问 → 交付时无法解释设计意图
