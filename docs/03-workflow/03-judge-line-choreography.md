# 03 · 判定线编排（演出设计）

> 同样是 500 个音符，普通谱是"打地鼠"，大师谱是"一支舞"。
> 差别 90% 来自判定线编排。

---

## 1. 判定线的三种身份

| 身份 | 是否承载 note | 作用 | zOrder |
|---|---|---|---|
| 演奏线 | ✅ | 让玩家打 | 高 |
| 演员线 | ❌ / 假 note | 纯视觉表演 | 低 |
| 功能线 | ❌ | UI 绑定、文字、纹理 | 按需 |

**关键认知**：「声嘶力竭」69 条线里只有约 15 条承载音符，其余 54 条全是演员。
「探窗」37 条线里只有 2 条主线承载了 366/355 个音符中的绝大部分。

> 所以：**线不是越多越好，是"角色越清晰越好"**。

---

## 2. 分组（judgeLineGroup）

分组不是文件夹，是**设计意图的声明**。

「探窗」的 9 个分组（教科书级）：

| # | 组名 | 线条 | 职能 |
|---|---|---|---|
| 0 | Default | 7 | 花瓣纹理 |
| 1 | 主线 | 2 | 演奏判定 |
| 2 | 特效 | 2 | 文字方块 |
| 3 | 表演1 | 3 | 闪烁线 |
| 4 | 表演2 | 3 | 扫描线 |
| 5 | 表演1.1 | 3 | 另一组闪烁 |
| 6 | 特殊主线 | 2 | 倒置音符 |
| 7 | 文字/图片 | 4 | 自定义纹理 |
| 8 | 表演3 | 3 | 渐隐线 |

我们的「Dangerous」只用了 2 组（Default / 特效）——**这就是差距**。

### 推荐分组模板（通用）

```
0  Main        演奏主线
1  Sub         副演奏线
2  Performance 表演线（闪烁/扫描/环绕）
3  Texture     纹理线（花瓣/雪花/光点）
4  Text        文字/歌词（textEvents）
5  UI          attachUI 绑定（暂停/连击/分数/进度条）
6  Effects      特殊演出（倒置、镜像、特写）
```

## 3. 坐标系与"用满全屏"

| 轴 | 范围 |
|---|---|
| X | -675 ~ 675 |
| Y | -450 ~ 450 |

**踩坑**：我们第一版所有 `moveX` 只在 ±20 内振荡，用户反馈"判定线很死板、全在中间"。

正确做法：

- 大位移段落：`moveX` 从 -600 扫到 600
- 纵向演出：`moveY` 从 400 降到 -400（"坠落感"）
- 环绕：`moveX = A*sin(t)`、`moveY = A*cos(t)`，A ≈ 400
- 特写：`scaleXEvents/scaleYEvents` 放大纹理

## 4. 事件密度：从"每 4 拍"到"每 1/16 拍"

这是"业余"和"专业"的分水岭。

| 谱面 | 表演线事件粒度 | 单线事件数 |
|---|---|---|
| 我们 v2/v5 | 每 4~8 拍 | 10~30 |
| 声嘶力竭（actor1） | 细 | 279 moveX / 435 alpha |
| Night Drawmers | **每 1/8 拍** | 阻尼振荡 100+ |
| 探窗（花瓣线） | **每 1/16 拍** | **1000+** |

### 4.1 怎么做"逐帧动画"

不要写一个 8 拍长的缓动事件，而是写 64 个 1/8 拍的事件：

```python
import math

def fade_oscillation(line, start_beat, end_beat, period=2.0, amp=10.0, step=0.125):
    """每 step 拍一个关键帧，正弦振荡"""
    b = start_beat
    events = []
    while b < end_beat:
        x = amp * math.sin(2 * math.pi * (b - start_beat) / period)
        events.append((bt_from_beat(b), x, 1))   # easing=1 线性
        b += step
    line.movex(events)
```

> 事件多不等于文件大：一个 event 约 200 字节，1000 个约 200KB，完全可接受。

### 4.2 阻尼振荡（"被敲击后抖动"）

Night Drawmers 的核心手法：振幅 4.69 → 0 衰减。

```python
def damped_shake(line, start_beat, amp=5.0, k=0.35, step=1/8):
    b = start_beat
    events = []
    i = 0
    while amp > 0.02:
        a = amp * math.exp(-k * i)
        events.append((bt_from_beat(b), a, 1))
        events.append((bt_from_beat(b + step/2), -a, 1))
        b += step
        i += 1
    line.movex(events)
```

### 4.3 烘焙：把"连续动画"采样成关键帧

花瓣飘落、粒子流、流光扫过——**别手 K，要烘焙。**

```python
from chart_builder import bake_curve

# 16 fps 采样，观感已经连续，成本却低一个数量级
for i in range(6):
    x = bake_curve(lambda b, i=i: 120 * math.sin(b * 0.7 + i), 0, 64, bpm=95, fps=16)
    y = bake_curve(lambda b, i=i: -260 + 8.5 * b, 0, 64, bpm=95, fps=16)
    chart.add_line(f"petal{i}", clickable=False).movex(x).movey(y)
```

实测依据（《浮生梦 探窗》）：6 条 `blossom` 线各 1 060 个位移帧、
时间跨度 200–261 s、帧间隔 0.25 s（16 fps），
贡献了全谱 18 245 帧里的大半 —— 而它不是手 K 的，是采样的。

| 采样率 | 观感 | 帧数（60 s） | 建议 |
|---|---|---|---|
| 8 fps | 略有跳帧 | 480 | 慢速飘落可接受 |
| **16 fps** | 连贯 | 960 | **默认** |
| 30 fps | 顺滑 | 1 800 | 高速流光 |
| 60 fps | 无差别 | 3 600 | 浪费，别超过 |

注意：`bake_curve` 的 `start/end` 单位是**拍**，`fps` 是**每秒**，
两者靠 `bpm` 换算（`step = bpm/60/fps`），变速曲记得分段调用。

## 5. 父子线（father）

```json
{ "Name": "drag-father", "father": -1 },
{ "Name": "drag-1", "father": 4 },
{ "Name": "drag-2", "father": 4 }
```

**原则**：
- 父线事件**少而精** → 控制整体位移
- 子线事件**多而密** → 各自旋转/缩放/抖动
- 改父线一处 = 整个家族跟着动，维护成本低

「声嘶力竭」的 7 组父线：

| 父线 | 子线 | 效果 |
|---|---|---|
| Main | HelpMe-Drag, Main-2/3/4 | 主判定 + 辅助 + Drag 视觉 |
| dragperformance-fatherline | drag-performance 等 4 条 | 4 线同步编舞 |
| text1-father | text1-up/left/down/right | 可移动文字方框 |
| text2/3/4-father | 各自 4 子线 | 同上 |

## 6. 速度曲线（speedEvents）

速度是**情绪**，不只是手感。

「声嘶力竭」16 段变速，范围 3 → 20：

| 拍 | 速度 | 段落意图 |
|---|---|---|
| 0 | 10 | 起速 |
| 27→31.5 | 10→20 | build-up 加速 |
| 31.75 | 7 | 骤降 = breakdown |
| 74 | 9 | 微调 |
| 126 | 10.5 | pre-chorus |
| 243 | 8 | 减速 |
| 500→501 | 9→12 | final drop |
| 504→512 | 12→3 | outro 拖尾 |

**手法**：
- 加速用短事件（2~4 拍内完成）
- 骤降要**在拍点上**，让玩家"踩空"
- `speedEvents` 负值 = 音符向上飞（可以做"倒流"奇观）

---

## 7. 透明度（alphaEvents）

- `end` 为**负数** → 隐藏该线及其所有 note（做"消失/出现"）
- 表演线常驻 `alpha` 100~200，避免抢视线
- 淡入淡出至少 0.5 拍，否则像闪烁
- UI 线的 alpha 控制要谨慎（别把连击数弄没了）

---

## 8. 纹理与 scaleX/scaleY

「探窗」用 126×126 的小花瓣图铺满屏幕：

```json
"extended": {
  "scaleXEvents": [{ "startTime": [...], "endTime": [...], "start": 3.0, "end": 3.0, "easingType": 1 }],
  "scaleYEvents": [{ ... }]
}
```

要点：
- 纹理线不承载 note
- `anchor` 设 `[0.5, 0.5]` 便于中心缩放
- 大图（2564×1312）直接铺，小图靠 scale 放大
- 用完 `alpha` 归零，不要同时显示所有纹理

### 8.1 把判定线当"精灵图层"（动画谱的核心手法）

当一条线只用来"显示一张图"时，它就等价于视频里的一个 sprite。
这件事做透了，谱面就从"音符文件"变成"动画片"（实例见
[`docs/04-reference/04-case-enchanted-love.md`](../04-reference/04-case-enchanted-love.md)：
287 条线、101 张贴图、零 shader、141 秒成片）。

| 能力 | 字段 | 用法 |
|---|---|---|
| 显示图片 | `Texture` | 填文件名（与 zip 内同名）；建议单张 ≤ 1000px |
| 缩放 | `extended.scaleX/YEvents` | 非等比 → 呼吸、拍扁、拉伸 |
| 位移 | `moveX/moveYEvents` | 常把道具停在 `x=±1800`（画外），需要时扫进来 |
| 旋转 | `rotateEvents` | 道具自转、整个舞台失衡 |
| 染色 | `extended.colorEvents` | **白图 + 染色**，一张图顶十种配色 |
| 倾斜 | `extended.inclineEvents` | 透视、速度感 |
| 进出场 | `alphaEvents` | 0→255→0 三段式，别忘记退场 |
| 覆盖关系 | `isCover: 1` | 音符到达判定线即消失（常规手感）；`0` 才允许穿透 |
| 图层 | `zOrder` | 背景负值、前景正值；同 z 按数组顺序 |

三条硬经验：

1. **拆部件，不要拼整图**。
   一个角色 = 头 / 身 / 影 / 道具，各自一条线，才能独立动。
2. **画外停靠**。道具默认停在屏幕外，用 `moveX` 扫入，
   一条线可以复用整曲，还自带运镜方向。
3. **三个层级物理隔离**：
   `永远可见（布景/角色）` / `按需出场（演出）` / `承载音符（演奏）`。
   混在一起必乱。

### 8.2 文字：没有 textEvents 时怎么办

| 方案 | 做法 | 适用 |
|---|---|---|
| 字母拼装 | 每个字母一张图、一条线，手动摆位 | 标题、短句（≤ 10 字） |
| 整句图片 | 整段文字渲染成 PNG，一条线显示 | 长句、字幕 |
| 多色变体 | 同句准备 3~8 个配色版本，同位置靠 alpha 切换 | 文字变色 |
| 染色 | 白字贴图 + `colorEvents` | 渐变变色（最省） |
| 不做字 | 用情绪特效代替（色偏、明暗、粒子） | 不想让文字干扰读谱 |

> 本谱用「字母拼装 + 多色变体」做出标题与结语；
> 26 条 `letter_*.png` 线，每个字母还能独立跳动。

## 9. 文字与 UI

### 9.1 textEvents 的三种用法

| 用法 | 例子 | 场景 |
|---|---|---|
| 歌词 | `"start": "从白天到黑夜"` | 副歌字幕 |
| 视觉标记 | `"start": "■"` / `"▁"` | 定位、装饰 |
| 叙事 | 整段制谱感言 | 结尾 |

### 9.2 attachUI

「Night Drawmers」把 7 个 UI 元素全部绑到判定线上：

| 值 | UI |
|---|---|
| `pause` | 暂停按钮 |
| `combonumber` | 连击数字 |
| `combo` | 连击标签 |
| `score` | 分数 |
| `bar` | 进度条 |
| `name` | 曲名 |
| `level` | 难度 |

> 慎用：UI 跟着线乱飞会影响可读性。适合"结尾演出"或"极简谱"。

## 10. 演出设计清单（写完对照）

- [ ] 每条线都有明确角色（写进 `Name`）
- [ ] 分组 ≥ 3 个，且语义清晰
- [ ] 至少 1 条纯表演线的事件数 > 100
- [ ] 大位移段落用到了 ±400 以上
- [ ] 有 1 处"音乐静但线在动"（反差）
- [ ] 有 1 处"线消失 → 突然出现"（alpha 负值）
- [ ] 速度曲线有 ≥ 4 段变化
- [ ] 没有线挡住演奏区的 note（zOrder 检查）
- [ ] 结尾有收束（alpha 归零 / 速度归零）

---

## 11. 反例

- ❌ 所有线都在中间 ±50 晃 → 死板
- ❌ 表演线 zOrder 高于演奏线 → 看不见 note
- ❌ 全曲一个速度 → 没有呼吸
- ❌ 每条线都塞满事件 → 视觉噪音
- ❌ 用特效代替编排 → "加了不如不加"

## 12. 视频层（`extra.json` 的 `videos`）

除了判定线，还有一层**独立的全屏视频**，不占用任何线资源：

```json
{
  "path": "bga1.mp4",
  "time": [386, 0, 1],
  "scale": "cropCenter",
  "alpha": 0.5,
  "dim": 0.3,
  "startTime": [0, 0, 1],
  "endTime": [18, 0, 1],
  "colorFilter": [0.0, 0.0, 1.0, 1.0]
}
```

| 字段 | 单位 | 说明 |
|---|---|---|
| `time` | 拍 | 视频出现的起始位置（`[386,0,1]` @117 BPM ≈ 197.9 s） |
| `startTime`/`endTime` | 秒 | 视频内部的裁切窗口（实测与素材时长吻合） |
| `scale` | — | `cropCenter` 裁切铺满、不拉伸 |
| `alpha` + `dim` | 0~1 | 半透明 + 压暗，**两者都要开** |
| `colorFilter` | RGBA | 给视频统一调色，比重新剪片便宜 |

三条硬规则：

1. **`alpha ≤ 0.6` 且 `dim ≥ 0.2`**，否则高速段读谱必崩
2. 视频放在**弱谱区**，别和爆发段抢注意力
3. 必须有**无视频降级**：客户端不支持时谱面仍完整

详见 [《巴拉莱卡》案例](../04-reference/06-case-balalaika.md#4-视频层extrajson-的-videos)。
