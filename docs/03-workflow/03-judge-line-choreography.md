# 03 · 判定线编排（演出设计）

> 同样是 500 个音符，普通谱是"打地鼠"，大师谱是"一支舞"。
> 差别 90% 来自判定线编排。

---

## 1. 判定线的三种身份

| 身份 | 是否承载 note | 作用 | zOrder |
|---|---|---|---|
| 演奏线 | ✅ | 让玩家打 | 高 |
| 演员线 | ❌ / 假 note | 纯视觉表演 | 低 |
| 功能线 | ❌ | UI 绑定、文字、纹理 | 按需 |

**关键认知**：「声嘶力竭」69 条线里只有约 15 条承载音符，其余 54 条全是演员。
「探窗」37 条线里只有 2 条主线承载了 366/355 个音符中的绝大部分。

> 所以：**线不是越多越好，是"角色越清晰越好"**。

## 2. 分组（judgeLineGroup）

分组不是文件夹，是**设计意图的声明**。

「探窗」的 9 个分组（教科书级）：

| # | 组名 | 线条 | 职能 |
|---|---|---|---|
| 0 | Default | 7 | 花瓣纹理 |
| 1 | 主线 | 2 | 演奏判定 |
| 2 | 特效 | 2 | 文字方块 |
| 3 | 表演1 | 3 | 闪烁线 |
| 4 | 表演2 | 3 | 扫描线 |
| 5 | 表演1.1 | 3 | 另一组闪烁 |
| 6 | 特殊主线 | 2 | 倒置音符 |
| 7 | 文字/图片 | 4 | 自定义纹理 |
| 8 | 表演3 | 3 | 渐隐线 |

我们的「Dangerous」只用了 2 组（Default / 特效）——**这就是差距**。

### 推荐分组模板（通用）

```
0  Main        演奏主线
1  Sub         副演奏线
2  Performance 表演线（闪烁/扫描/环绕）
3  Texture     纹理线（花瓣/雪花/光点）
4  Text        文字/歌词（textEvents）
5  UI          attachUI 绑定（暂停/连击/分数/进度条）
6  Effects      特殊演出（倒置、镜像、特写）
```

## 3. 坐标系与"用满全屏"

| 轴 | 范围 |
|---|---|
| X | -675 ~ 675 |
| Y | -450 ~ 450 |

**踩坑**：我们第一版所有 `moveX` 只在 ±20 内振荡，用户反馈"判定线很死板、全在中间"。

正确做法：

- 大位移段落：`moveX` 从 -600 扫到 600
- 纵向演出：`moveY` 从 400 降到 -400（"坠落感"）
- 环绕：`moveX = A*sin(t)`、`moveY = A*cos(t)`，A ≈ 400
- 特写：`scaleXEvents/scaleYEvents` 放大纹理

## 4. 事件密度：从"每 4 拍"到"每 1/16 拍"

这是"业余"和"专业"的分水岭。

| 谱面 | 表演线事件粒度 | 单线事件数 |
|---|---|---|
| 我们 v2/v5 | 每 4~8 拍 | 10~30 |
| 声嘶力竭（actor1） | 细 | 279 moveX / 435 alpha |
| Night Drawmers | **每 1/8 拍** | 阻尼振荡 100+ |
| 探窗（花瓣线） | **每 1/16 拍** | **1000+** |

### 4.1 怎么做"逐帧动画"

不要写一个 8 拍长的缓动事件，而是写 64 个 1/8 拍的事件：

```python
import math

def fade_oscillation(line, start_beat, end_beat, period=2.0, amp=10.0, step=0.125):
    """每 step 拍一个关键帧，正弦振荡"""
    b = start_beat
    events = []
    while b < end_beat:
        x = amp * math.sin(2 * math.pi * (b - start_beat) / period)
        events.append((bt_from_beat(b), x, 1))   # easing=1 线性
        b += step
    line.movex(events)
```

> 事件多不等于文件大：一个 event 约 200 字节，1000 个约 200KB，完全可接受。

### 4.2 阻尼振荡（"被敲击后抖动"）

Night Drawmers 的核心手法：振幅 4.69 → 0 衰减。

```python
def damped_shake(line, start_beat, amp=5.0, k=0.35, step=1/8):
    b = start_beat
    events = []
    i = 0
    while amp > 0.02:
        a = amp * math.exp(-k * i)
        events.append((bt_from_beat(b), a, 1))
        events.append((bt_from_beat(b + step/2), -a, 1))
        b += step
        i += 1
    line.movex(events)
```

## 5. 父子线（father）

```json
{ "Name": "drag-father", "father": -1 },
{ "Name": "drag-1", "father": 4 },
{ "Name": "drag-2", "father": 4 }
```

**原则**：
- 父线事件**少而精** → 控制整体位移
- 子线事件**多而密** → 各自旋转/缩放/抖动
- 改父线一处 = 整个家族跟着动，维护成本低

「声嘶力竭」的 7 组父线：

| 父线 | 子线 | 效果 |
|---|---|---|
| Main | HelpMe-Drag, Main-2/3/4 | 主判定 + 辅助 + Drag 视觉 |
| dragperformance-fatherline | drag-performance 等 4 条 | 4 线同步编舞 |
| text1-father | text1-up/left/down/right | 可移动文字方框 |
| text2/3/4-father | 各自 4 子线 | 同上 |

## 6. 速度曲线（speedEvents）

速度是**情绪**，不只是手感。

「声嘶力竭」16 段变速，范围 3 → 20：

| 拍 | 速度 | 段落意图 |
|---|---|---|
| 0 | 10 | 起速 |
| 27→31.5 | 10→20 | build-up 加速 |
| 31.75 | 7 | 骤降 = breakdown |
| 74 | 9 | 微调 |
| 126 | 10.5 | pre-chorus |
| 243 | 8 | 减速 |
| 500→501 | 9→12 | final drop |
| 504→512 | 12→3 | outro 拖尾 |

**手法**：
- 加速用短事件（2~4 拍内完成）
- 骤降要**在拍点上**，让玩家"踩空"
- `speedEvents` 负值 = 音符向上飞（可以做"倒流"奇观）

---

## 7. 透明度（alphaEvents）

- `end` 为**负数** → 隐藏该线及其所有 note（做"消失/出现"）
- 表演线常驻 `alpha` 100~200，避免抢视线
- 淡入淡出至少 0.5 拍，否则像闪烁
- UI 线的 alpha 控制要谨慎（别把连击数弄没了）

---

## 8. 纹理与 scaleX/scaleY

「探窗」用 126×126 的小花瓣图铺满屏幕：

```json
"extended": {
  "scaleXEvents": [{ "startTime": [...], "endTime": [...], "start": 3.0, "end": 3.0, "easingType": 1 }],
  "scaleYEvents": [{ ... }]
}
```

要点：
- 纹理线不承载 note
- `anchor` 设 `[0.5, 0.5]` 便于中心缩放
- 大图（2564×1312）直接铺，小图靠 scale 放大
- 用完 `alpha` 归零，不要同时显示所有纹理

## 9. 文字与 UI

### 9.1 textEvents 的三种用法

| 用法 | 例子 | 场景 |
|---|---|---|
| 歌词 | `"start": "从白天到黑夜"` | 副歌字幕 |
| 视觉标记 | `"start": "■"` / `"▁"` | 定位、装饰 |
| 叙事 | 整段制谱感言 | 结尾 |

### 9.2 attachUI

「Night Drawmers」把 7 个 UI 元素全部绑到判定线上：

| 值 | UI |
|---|---|
| `pause` | 暂停按钮 |
| `combonumber` | 连击数字 |
| `combo` | 连击标签 |
| `score` | 分数 |
| `bar` | 进度条 |
| `name` | 曲名 |
| `level` | 难度 |

> 慎用：UI 跟着线乱飞会影响可读性。适合"结尾演出"或"极简谱"。

## 10. 演出设计清单（写完对照）

- [ ] 每条线都有明确角色（写进 `Name`）
- [ ] 分组 ≥ 3 个，且语义清晰
- [ ] 至少 1 条纯表演线的事件数 > 100
- [ ] 大位移段落用到了 ±400 以上
- [ ] 有 1 处"音乐静但线在动"（反差）
- [ ] 有 1 处"线消失 → 突然出现"（alpha 负值）
- [ ] 速度曲线有 ≥ 4 段变化
- [ ] 没有线挡住演奏区的 note（zOrder 检查）
- [ ] 结尾有收束（alpha 归零 / 速度归零）

---

## 11. 反例

- ❌ 所有线都在中间 ±50 晃 → 死板
- ❌ 表演线 zOrder 高于演奏线 → 看不见 note
- ❌ 全曲一个速度 → 没有呼吸
- ❌ 每条线都塞满事件 → 视觉噪音
- ❌ 用特效代替编排 → "加了不如不加"
