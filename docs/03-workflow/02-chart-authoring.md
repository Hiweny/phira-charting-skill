# 02 · 谱面编写流程

> 目标：从"设计笔记"到"可导入、可玩、好看"的 chart.json。

---

## 1. 写谱顺序（严格按此）

```
音乐分析笔记
   ↓
① 确定 BPM / offset / 时长
   ↓
② 划段落 + 定 NPS 曲线
   ↓
③ 设计判定线舞台（分组 / 角色 / 父子）
   ↓
④ 写主演奏线的 note
   ↓
⑤ 写辅助演奏线（多层）
   ↓
⑥ 写表演线动画（这个最花时间）
   ↓
⑦ 加特效 extra.json
   ↓
⑧ 自检 + 打包 + 实测
```

**别跳 ③ 直接写 note**。先想清楚"这个舞台有几条线、每条线演什么"，后面才不会返工。

---

## 2. 用 chart_builder 而不是手搓 JSON

```python
from chart_builder import Chart, note, bt

c = Chart(
    bpm=128.0,
    song="song.mp3",
    name="曲名",
    charter="愉是心上结",
    level="IN Lv.13",
    difficulty=13.0,
    duration=192.0,
)

main = c.add_line("Main", group=0, z_order=50)
main.notes.append(note(1, bt(4, 0), x=0))
main.notes.append(note(2, bt(4, 1), bt(6, 1), x=-200))   # Hold
main.movex([(bt(0,0), 0), (bt(4,0), 120, 1)])
main.speed([(bt(0,0), 10.0)])

c.save("chart.json")
c.save_info("info.yml")
c.save_extra("extra.json")
```

> 库内部已经处理了：整数三元组、必填字段、control 数组、事件 10 字段。
> **不要绕过库手写 dict**，除非你在改库本身。

## 3. 难度与密度

### 3.1 NPS（每秒音符数）参考

| 难度 | 平均 NPS | 峰值 NPS | 备注 |
|---|---|---|---|
| IN 10~11 | 2~3 | 4 | 以 Tap/Hold 为主 |
| IN 12~13 | 3~5 | 7 | 引入 Drag 流、双线 |
| IN 14~15 | 5~7 | 10 | 多线交错、密集 Flick |
| IN 16+ | 7~10+ | 14+ | 极限，慎做 |

**设计原则**：NPS 是一条曲线，不是常数。
典型形状：

```
Intro 1.5 → Verse 3 → Pre 4 → Chorus 6 → Bridge 1.5 → Final 7 → Outro 1.5
```

### 3.2 音符类型比例（参考精品谱）

| 类型 | 声嘶力竭 | Night Drawmers | 建议区间 |
|---|---|---|---|
| Tap | 43.6% | — | 40~55% |
| Drag | **47.2%** | — | 20~45%（演出型谱面可高） |
| Hold | 5.1% | — | 5~18% |
| Flick | 4.1% | — | 3~8% |

> Drag 超过 50% 会显得"糊"，低于 15% 会显得"干"。

### 3.3 密度突变规则

- 相邻段落 NPS 变化 ≤ 2 倍，除非是刻意的 Drop。
- 高潮前一拍**减少**音符（留白），高潮第一拍**爆发**——这是最有效的爽点手法。
- 静音段 NPS = 0 也可以，让判定线独自表演。

## 4. 位置设计

### 4.1 离散坐标制（强烈推荐）

用固定的对称坐标，而不是连续随机：

```python
LANES = [-490, -368, -306, -184, -122, 0, 122, 184, 306, 368, 416, 490]
```

好处：
- 视觉整齐、可读性强
- 左右对称，符合人体工学
- 避免"note 全挤中间"

### 4.2 常用走位模式

| 模式 | 描述 | 用途 |
|---|---|---|
| 阶梯 | -490 → -306 → -122 → 122 → 306 → 490 | 上行/下行旋律 |
| 对称 | 左右同时落点 | 重音、和弦 |
| 交替 | 左→右→左→右 | 稳定八分 |
| 内外 | 中心 → 外侧 | 展开段落 |
| 聚拢 | 外侧 → 中心 | 收束段落 |
| 散开 | 中心 → 外侧 | Drop |
| 河道 | 固定 3~4 个位置 | 高密度段，保证可读 |

### 4.3 绝对禁止

- 同一个 `(时间, 线, positionX)` 上放两个 note（重叠 = 必然漏判）
- 相邻 note 间距小于 20px 且时间差小于 1/8 拍（视觉糊成一团）
- 演奏线移到屏幕外还继续放 note（看不见）

## 5. 音符类型选择决策树

```
这个声音是"点"还是"线"？
├─ 线（人声长音/弦乐/铺底）
│   └─ Hold（长度 = 声音持续）
└─ 点
    ├─ 重音 / 主拍 → Tap
    ├─ 反拍 / 镲片 / 转折 → Flick
    └─ 密集装饰 / 过场 → Drag
```

补充规则：
- **Hold 不要超过 2 拍**（除非是极慢抒情段），否则玩家手会僵。
- **Flick 每 4 拍最多 1~2 个**，多了像抽筋。
- **Drag 可以成串**（1/8、1/16 流），但要有明确路径感。
- **Tap 连打**（jack）超过 8 个要换手/换位。

## 6. 多线分工

| 线角色 | 承载 note | 事件密度 | zOrder |
|---|---|---|---|
| Main（主线） | 60~90% | 中 | 高（50+） |
| Sub（副线） | 10~30% | 中 | 高 |
| Performance（表演） | 0~5%（假 note） | **极高** | 低（-50） |
| Texture（纹理） | 0 | 中 | 最低 |
| Text（文字） | 0 | 低 | 中 |
| UI | 0 | 低 | 最高 |

规则：
- 演奏线 **最多 3~4 条**，多了玩家看不过来。
- 表演线可以 10~40 条，它们不参与判定。
- 所有承载 note 的线，`zOrder` 必须高于表演线/纹理线。

## 7. 完整示例骨架：演唱会式谱面

以 MJ《Dangerous》为例（见 `examples/case-dangerous/`）：

| 线 | 角色 | notes | 说明 |
|---|---|---|---|
| MJ | 主表演 + 主判定 | 大量 | 中央，随鼓点位移/旋转，模拟舞者 |
| Left / Right | 副判定 | 中 | 左右声道分轨，对称 |
| Spotlight | 纯表演 | 0 | 聚光灯扫射，alpha 起伏 |
| Rhythm | 纯表演 | 0（或假 note） | 脉冲条，跟底鼓 |
| Special | 纯表演 | 0 | 高潮特写，旋转炸开 |

设计要点：
- **主线的运动 = 舞蹈**：静止 → 爆发 → 滑步（Drag 流）→ 45° 倾斜（rotate）
- **副歌用"聚光灯"叙事**：Spotlight 从一侧扫到另一侧
- **Bridge 段降速**：`speedEvents` 从 12 降到 5，制造"时间变慢"
- **结尾**：所有线 alpha 归零，只留主线淡出

## 8. 时间对齐技巧

```python
# 秒 → beat → 三元组
from fractions import Fraction

def sec_to_bt(sec, bpm, max_den=16):
    beat = sec * bpm / 60.0
    f = Fraction(beat).limit_denominator(max_den)
    m = int(f)
    return [m, f.numerator - m * f.denominator, f.denominator] if f.denominator else [m, 0, 1]
```

- 先把所有"想放 note 的秒数"列出来，再统一转 beat，避免逐个手算。
- 对齐鼓点时允许 ±1/16 拍的容差，听感上察觉不到。
- **不要**为了对齐而把 note 放到 1/64 拍这种人类打不出来的位置。

## 9. 生成后的第一轮人工检查

1. 主线 note 是否覆盖了所有强拍？
2. 有没有连续 8 个以上同位置 Tap？
3. 最长 Hold 有多长？（>2 拍就要确认）
4. 副歌 NPS 是否明显高于主歌？
5. 最后 5 秒是否收干净了？
6. 有没有 note 落在 `chartTime` 之外？

跑 `validate_chart.py --report` 会自动给出以上统计。

- v1：骨架正确即可（能导入、能玩）
- v2：密度与位置设计

**每版都保留 zip**。不要在一版里同时改四类东西。
