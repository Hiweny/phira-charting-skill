# 05 · 难度曲线与画面比例

> 难度不是"NPS 数字"，比例不是"随手填的坐标"。
> 两者共同决定一件事：**玩家能不能看懂、能不能打到、爽不爽。**

---

## 1. 感知难度公式

```
感知难度 ≈ 密度(NPS) × 手型复杂度 × 视觉识别成本 × 节奏复杂度
```

四个因子任一爆表，玩家就会觉得"这谱有病"，哪怕另外三个都很低。

| 因子 | 低 | 高 |
|---|---|---|
| 密度 | < 3 nps | > 8 nps |
| 手型 | 单指交替、同 x 往返 | 跨屏跳跃、双押+长条混合、连续 Flick |
| 视觉识别 | 线固定、note 大、背景暗 | 线高速旋转、note 小、特效盖屏 |
| 节奏 | 4 分稳定 | 切分、三连、变速、反拍 |

**设计法则**：同一时刻最多让**两个**因子处于高位。
高密度段 → 线要稳、note 要大；高速演出段 → 密度要降。

## 2. 定级参考表

Phira 社区常用难度区间（`difficulty` 数值，与 `level` 字符串对应）：

| 区间 | 标称 | 峰值 NPS | 手型特征 | 适合人群 |
|---|---|---|---|---|
| 1–4 | EZ / HD | ≤ 2.5 | 单指、单线、4 分 | 第一次玩 |
| 5–8 | HD / IN | 2.5–4.5 | 双指交替、少量 8 分 | 休闲 |
| 9–11 | IN | 4.5–6.5 | 跨线、双押、短 Hold | 常规玩家 |
| 12–13 | IN | 6.5–8.5 | 三连、Flick 串、线移动中打 | 熟练 |
| 14–15 | AT / IN | 8.5–11 | 高速双押、视觉干扰下打 | 硬核 |
| 16+ | AT | > 11 | 极限手速 + 强读谱 | 极少数 |

> 定级宁可**保守半级**。玩家觉得"这谱标 12 但打起来像 13"是加分；
> 反过来"标 15 结果只有 12"会被差评。

### NPS 峰值校验

```bash
python3 tools/preview_render.py <工程> --stats
# 关注 peak_nps_1s（1 秒窗口内的最大音符数）
```

`peak_nps_1s` 与标称难度的对应关系参考上表。**注意它统计的是"全部音符"**，
含 Hold 尾判与 Drag，所以真实手速需求通常略低于该值。

## 3. 难度曲线形状

难度曲线要**跟随音乐能量**，但必须满足两条物理约束：

1. **相邻段落的 NPS 跳变 ≤ 2.5**：1.5 → 8.0 的断崖会让玩家懵。
2. **峰值只出现 1~2 次**：第一次在"第一次副歌"，最后一次在"最终副歌"。

```
推荐形状（张力随段落单调上升，但有呼吸）：

NPS
 9 |                    ██        ███
 7 |              ██    ████   ██ ████
 5 |        ██   ████  ██████ █████████
 3 |   ██  ████ █████████████████████████
 1 | ██████████████████████████████████████
   +----------------------------------------
     Intro Verse Build  Chorus  Brk  Final
```

### 段落内的微观曲线

- **进入副歌**：第 1 拍留一个空拍，第 2 拍起密度拉满 → 制造"砸下来"的落差
- **副歌中段**：允许降 1~2 nps 做"呼吸"，否则玩家注意力会崩
- **Bridge / 静音**：NPS 可以跌到 0。**静音不是失误，是设计**
- **收尾**：最后一拍给一个明确的重音，然后立刻归零

## 4. 画面比例

### 4.1 坐标系

| 量 | 值 | 说明 |
|---|---|---|
| `RPE_WIDTH` | 1350 | 逻辑宽度 |
| `RPE_HEIGHT` | 900 | 逻辑高度 |
| note x 可用范围 | `[-675, 675]` | 超出即出屏 |
| note y 视觉区 | `[-450, 450]` | y 通常靠 `positionY` 微调 |

> 纯数学坐标是 ±675，但**实际手感区建议 ±500**。
> 贴边的 note 在手机上会被手指挡住，也被刘海/圆角裁掉。

### 4.2 常用离散 x 坐标（对称、好读、好记）

```
±490  外框        视觉边界
±368  半外框      双手舒适极限
±306  中区        常见双押位
±184  内区        主体音符区
±122  核心区      密集段
  0   正中        长音、Flick 落点
```

**不要用随机浮点**（如 137.42）。同一段里反复用同一组坐标，玩家能建立肌肉记忆；
坐标全乱会让读谱成本暴涨。

### 4.3 note 尺寸

| 场景 | 建议 |
|---|---|
| 低密度抒情段 | 标准尺寸，留白 |
| 高密度副歌 | 可略缩小（靠 `noteUniformScale`）避免重叠 |
| 重音 | 单独放大 1.2~1.5 倍（视觉重音） |
| 装饰性 Drag | 缩小 + 降透明度，弱化存在感 |

### 4.4 判定线长度 `lineLength`

| 长度 | 效果 | 适用 |
|---|---|---|
| 短（< 300） | 精致、局部、像乐器 | 特写、点缀 |
| 中（600–900） | 平衡，最通用 | 主演奏线 |
| 长（≥ 1350） | 贯穿全屏、有压迫感 | 高潮、终章、Drop |

> 长线 + 大幅旋转 = 视觉冲击，但也最容易遮挡 note。
> **判定线长度和 note 密度成反比**。

### 4.5 屏幕占比自查

一条经验规则：

- 单段内，**被 note 覆盖的 x 区间** 应 ≥ 屏幕宽度的 50%（否则全挤中间）
- 全曲，**判定线 x 覆盖** 应接近 `[-675, 675]`（否则舞台没用满）
- 任何时刻，**屏幕中心 400×260 区域**不应同时出现 > 6 个 note（会糊成一团）

对应指标：

```bash
python3 tools/preview_render.py <工程> --stats
# x_range           音符横向覆盖
# x_std             音符横向离散度（越大越铺开）
# line_x_cover      判定线横向覆盖（应接近 ±675）
```

## 5. 可视性阈值（硬指标）

| 指标 | 合格线 | 含义 |
|---|---|---|
| `hidden_notes` | 0 | 命中瞬间判定线不可见的 note 数 |
| `offscreen_hit_notes` | ≤ 总音符 2% | 命中点跑出屏幕的 note 数 |
| `approach_visible_ratio` | ≥ 0.80 | 命中前 0.4s 已进入画面的比例 |
| `approach_dist_median` | 350–650 px | 命中前 0.4s 的下落距离 |

> `approach_visible_ratio` 受判定线纵向位置影响：线在屏幕中心时，默认速度 10 的 note
> 只有约 0.37s 可读时间，该比例会偏低（0.1~0.5）。想让玩家更早看到，
> **把演奏线往下放**（`yControl` 负值）或降低 `speedEvents`，而不是一味加速。

`approach_dist_median` 太低 → note 几乎是"贴着线突然出现"，读不了；
太高 → 下落太快，玩家来不及反应。

> **画面里同时可见的 note 数量 ≈ NPS × 单 note 可读时长。**
> 想让画面"看起来很满"，两条路：加密度，或降速（让每个 note 在屏上待更久）。
> 降速通常比加密度更安全——手感不变差，视觉先变丰富。

**调整手段**：改 `speedEvents`（全曲下落速度）、改 `speed`（单音符）、
改 `sizeControl`、改判定线位置让 note 提前进入视野。

## 6. 难度节奏的"呼吸"设计

高级谱面都有**故意留白**：

- 每 8~16 拍必须有一次"低密度窗口"（哪怕只有 2 拍）
- 长 Hold 期间不要再叠 Tap（除非是刻意的双押技巧）
- 强演出段（线大幅移动/特效）同期降低 note 密度
- 连续 3 秒以上满密度 = 玩家手指会僵

---

## 7. 验收

- [ ] `peak_nps_1s` 与 `difficulty` 标称匹配
- [ ] 相邻段落 NPS 跳变 ≤ 2.5
- [ ] `line_x_cover` 覆盖 ≥ 80% 的屏幕宽度
- [ ] `hidden_notes == 0`，`offscreen_hit_notes` ≤ 2%
- [ ] `approach_visible_ratio` ≥ 0.80（线在屏幕中心时会天然偏低，见上）
- [ ] 存在至少 2 处"呼吸窗口"
- [ ] 最难的一段，你自己在脑内过一遍：手指够用吗？
