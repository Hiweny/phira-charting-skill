## 2. 最重要的一条：精品谱多数**不是**动画谱

10 张里 **7 张零贴图、零 shader**，帧/音符集中在 **3~6**。

| 类型 | 数量 | 特征 |
|---|---|---|
| 纯线谱（手感/技术向） | 7 | 帧/音符 3~6，判定线 17~72 |
| 演出向 | 3 | 78436（20.4）、84452（16.2）、84416（12.1） |

也就是说：**"精品"的门槛是音乐契合与手感，不是演出量。**
我此前从《enchanted love》《巴拉莱卡》得出的"精品 = 高帧密度"是**取样偏差** ——
这两张本来就是"演出谱"，在同分数段里属于少数派。

修正后的判断顺序：

```
先看手感是否对得上节奏 → 再看结构是否清晰 → 最后才看演出量
```

## 3. 难度档位的编排规律

| 档位 | 音符 | 事件帧 | 帧/音符 | 帧/秒 |
|---|---|---|---|---|
| Lv.5（EZ） | 182 | 526 | 2.9 | 3.7 |
| Lv.9 | 107 | 1 298 | 12.1 | 16.7 |
| Lv.12–14 | 428~1 267 | 3 950~6 951 | 3.8~16.2 | 23~47 |
| Lv.15–16 | 1 250~1 574 | 5 230~25 441 | 3.8~20.4 | 22~92 |
| Lv.17–18 | 1 364~2 320 | 6 887~11 768 | 5.0~5.1 | 46~72 |

**结论：随着难度上升，帧/音符反而收敛到 4~6。**
因为高难度谱的帧数被音符本身撑满了，演出必须让位给可读性。
Lv.5 的 2.9 说明：**简单谱几乎不用做演出**，做了反而干扰新手。

## 4. 两个极端个案

### 4.1 Drag 风暴：83844（Lv.13）

- **Drag 1 090 / 1 267 = 86%**，Tap 只有 88，Flick 仅 40
- 峰 NPS **160**（最大同时刻堆叠 7 键，持续约 23 击/秒）
- 有 175 个 `isFake` 假音符（已从统计中排除）

这是"长按流"：Drag 不需要抬手、判定宽松，于是可以把密度堆到极限。
**注意：不是 Flick。** 我最初把 `type 3/4` 弄反，写成了"Flick 风暴"，
核对 prpr 源码（`2 => Hold, 3 => Flick, 4 => Drag`）后才发现整张表都错位了。

### 4.2 氛围谱：84256（Lv.12）

- 17 条线、618 音符、帧/音符 6.4
- 带 **3 个 rpen shader**：`rain_pr.glsl`、`snow_pr.glsl`、`glow_effect_pr.glsl`

```glsl
// @rpen-template {"name":"rain_pr","chart":"好きな隙間","version":1}
// @rpen-builtin
#version 100
```

这是社区的一套 shader 模板体系（rpen），提供**雨/雪/辉光**等后处理，
用 `effectObjects` 挂载。技能此前完全没有覆盖这一层。

## 5. 技能缺口清单（按优先级）

| 优先级 | 缺口 | 证据 | 现状 |
|---|---|---|---|
| **P0** | `isFake` 假音符 | 83844 有 175 个；多数谱 10~40 个 | ✅ 统计已排除，builder 仍无开关 |
| **P0** | `textEvents` 文字系统 | 3/10 谱使用；可做曲名/Staff/剧情字幕 | ❌ 只有一段描述，无字段规范与 API |
| **P0** | PEC 格式 | 82096 是 `.pec`（官方格式） | ✅ 已能统计；builder 仍只产 RPE |
| **P1** | shader / rpen | 84256 带雨雪辉光三件套 | ❌ 无 |
| **P1** | GIF 判定线 | 样本中有 1 例 `gifEvents` + `.gif` | ❌ 渲染只取首帧 |
| **P1** | `META.offset` 语义 | 见 `-300`、`304`、`40` 等值 | ❌ 文档未写清音画同步 |
| **P2** | `multiLineString` | **18/18 谱都有**，是 RPE 默认字段 | ⚠️ 之前误当"隐藏特效"，已修正 |
| **P2** | 父子线完整语义 | 142 线次使用 | ⚠️ 有基础文档，缺继承边界案例 |

### 立即可以补的三件事

1. `chart_builder` 增加 `fake=True`（假音符）与 `text()`（文字事件）两个 API
2. 写 `docs/02-pitfalls/` 下的 `textEvents` 字段规范（start/end 双端文本、bezier、easing）
3. 自检渲染里 fake 音符被**置灰**（便于排查），但实机是**正常显示** ——
   所以看联系表判断"画面是否和实机一致"时，要先把置灰的那些排除掉
