# 横向基准：8 张谱的量化体检

> 结论先行：**精品谱之间的差异不在"音符多少"，而在"每颗音符背后花了多少帧"。**
> 本页数据由 [`tools/chart_stats.py`](../../tools/chart_stats.py) 全自动生成，可复现。

## 0. 怎么复现

```bash
python3 tools/chart_stats.py samples/*              # Markdown 表格
python3 tools/chart_stats.py samples/enchanted --json   # 单谱全字段
python3 tools/chart_stats.py samples/enchanted --timeline   # 每 10 秒事件密度
```

它回答的不是"好不好听"，而是**作者把时间花在哪了**：

| 指标 | 它真正衡量什么 |
|---|---|
| `判定线` | 舞台规模（多少块独立运动的面板） |
| `非默认贴图线` | 美术投入（有多少线用的是自制图） |
| `贴图` | 素材库大小 |
| `事件帧` / `帧每秒` | 编排密度（手 K 的工作量） |
| `帧/音符` | **这是动画还是谱面**的分界线 |
| `峰NPS` / `均NPS` | 演奏强度与爆发 |
| `Hold%` | 长条作为"呼吸"的使用比例 |

## 2. 五个能直接用的结论

### 2.1 Flick 占比被严重低估：精品谱 30%~54%

| 谱面 | Tap | Drag | Hold | **Flick** |
|---|---|---|---|---|
| 浮生梦 探窗 | 124 | 39 | 17 | **214 (54%)** |
| Night Drawmers | 370 | 105 | 22 | **455 (48%)** |
| 声嘶力竭 | 811 | 95 | 76 | **879 (47%)** |
| 鳥の詩 | 428 | 250 | 81 | 322 (30%) |
| enchanted love | 311 | 123 | 52 | **214 (31%)** |

新手谱的典型构成是"90% Tap"。而精品谱里 **Flick 常常是第二大甚至第二大等于 Tap**。

原因很实在：

- Flick **不要求 x 精度**（划到就算），是高速段的"便宜密度"
- Flick 有**方向感**，天然贴合鼓组与弦乐的"甩"
- 大段 Tap 会让手感变成"打字"，Flick 提供**手腕动作**

可操作规则：

```
副歌 / 高潮段：Flick 占比拉到 30%~45%
主歌 / 叙事段：回到 Tap 60%+，Flick 降到 15% 以下
Hold 全程 4%~10%，只在"呼吸点"和"长音"用，别用来占密度
```

`DNA` 是反例：Hold 11%、峰 NPS 18、帧/音符 3.3 —— 纯演奏向，也成立，但它靠的是
**高密度副歌**而不是演出。

### 2.2 演出型谱面的 X:Y 位移比透露"画布还是舞台"

| 谱面 | moveX | moveY | X:Y | 说明 |
|---|---|---|---|---|
| Night Drawmers | 11 998 | 4 049 | **3.0 : 1** | 横向运镜为主，像镜头推拉 |
| enchanted love | 4 751 | 3 890 | 1.2 : 1 | 舞台有纵深，双向都动 |
| 浮生梦 探窗 | 8 223 | 7 599 | **1.1 : 1** | 接近 1:1 → 全屏作画 |
| 声嘶力竭 | 2 776 | 2 324 | 1.2 : 1 | 均衡 |
| 鳥の詩 | 3 602 | 2 297 | 1.6 : 1 | 偏横向 |

**X:Y ≈ 1 时，作者是在"用判定线画画"**（探窗把线当笔，一帧一帧拼图案）。
**X:Y > 2.5 时，作者是在"做镜头"**（Night Drawmers 的线像摄像机轨道）。

想画图案就别怕 Y 多；想稳手感就让 Y 少动，M 型走位会毁掉读谱。

### 2.3 变速是"演出"，不是"难度"

| 谱面 | speedEvents |
|---|---|
| enchanted love | **602** |
| 鳥の詩 | 286 |
| 声嘶力竭 | 227 |
| Night Drawmers | 221 |
| 浮生梦 探窗 | **37** |

探窗几乎不变速（37 次），却拿到 46.3 帧/音符 —— 但见 §2.6，那个数字大半是烘焙出来的。
反过来说：**变速一多，读谱成本立刻上升**，没有画面支撑的变速是在给玩家添堵。

### 2.4 3D（incline）在样本里是 0

8 张谱，`inclineEvents` 有效值全为 0。也就是说：

- 3D 判定线在社区精品谱里**尚未成为标配**
- 它是**差异化机会**：用得好是记忆点，用不好是眩晕源
- 建议：一条谱最多 2~3 段 incline，且只用于"镜头俯冲/翻转"的瞬间

### 2.5 时长与线数是弱相关，与帧数才是强相关

稻香 572 秒只有 8 632 帧；探窗 261 秒却有 18 245 帧。
**线数不重要，帧/秒才重要。** 一条线可以撑 30 秒（enchanted 的 L0），
二十条线也可以只在最后 5 秒集体登场。

### 2.6 平均值会骗人：探窗的 82% 集中在最后 60 秒

把探窗的事件按 10 秒分桶，看到的是完全不同的故事：

| 区段 | 事件帧/10s | 发生了什么 |
|---|---|---|
| 0–10 s | 671 | 开场动画 |
| 10–200 s | 3 ~ 140 | **正常谱面**，几乎没有演出 |
| 200–261 s | **2 176 ~ 2 462** | 终章爆发 |

而终章的来源是 **6 条 `blossom*.png` 花瓣线**，每条的构成是：

```
moveXEvents 1060 帧 / moveYEvents 1061 帧 / rotateEvents 26 帧 / alphaEvents 5 帧
时间跨度 200–261 s，帧间隔 ≈ 0.25 s（16 fps）
```

也就是说：**这是把一段"花瓣飘落"的参数化动画，按 16 fps 采样烘焙成关键帧**，
不是逐帧手 K 的精细编排。6 条线 × 约 2 000 帧 ≈ 12 000+ 帧，
直接吃掉了全谱 18 245 帧里的大半。

由此得到两条方法论：

1. **平均指标必须配时间分布看。** 单看"帧/音符 46.3"会误判成"通篇精雕"，
   实际是"200 秒普通 + 60 秒爆发"。
2. **烘焙不是作弊，是正确工程。** 16 fps 的位移采样肉眼看完全连续，
   成本却远低于手 K。想要粒子/飘落/流光，就该这么干。

```python
# 生成花瓣线的最小骨架（16 fps 采样）
for i, t in enumerate(frange(200, 261, 0.0625)):
    x = x0 + amp * math.sin(t * w + phase)
    y = y0 - fall_speed * t
    move_x.append(ev(t, x)); move_y.append(ev(t, y))
```

## 3. 三档目标配置（照着填就能定风格）

拿到一首歌，先选档，再谈细节。

| | A 纯演奏型 | B 演出型 | C 动画型 |
|---|---|---|---|
| 参照 | DNA / 西厢寻他 | 鳥の詩 / 声嘶力竭 | enchanted love / 探窗 |
| 判定线 | 20~60 | 60~80 | 200+ |
| 非默认贴图线 | 0 | ≤10 | 200+ |
| 帧/音符 | 3~10 | 10~30 | 20~50 |
| 帧/秒 | <20 | 20~50 | 50~80 |
| Flick 占比 | 25%~35% | 30%~45% | 30%~50% |
| Hold 占比 | 5%~10% | 4%~7% | 4%~8% |
| 变速 | 少而狠 | 中等 | 多但都配画面 |
| 工作量重心 | 排布与手感 | 段落转场 | 素材与编排 |
| 风险 | 同质化 | 演出盖过演奏 | 音符被淹没 |

**别混档**：C 档的画面配 A 档的音符密度，会变成"看片不玩谱"；
A 档的线数硬塞 C 档的演出，会变成"线乱飞但没内容"。

## 4. 用这张表做自检

自己写完一张谱，跑一遍 `chart_stats.py`，然后问三个问题：

1. 我的 **帧/音符** 落在哪一档？和我想做的风格一致吗？
2. 我的 **Flick 占比** 够不够支撑副歌的爆发？会不会全程 Tap 打字机？
3. 我的 **moveX : moveY** 是画布型还是镜头型？如果是镜头型，
   有没有哪一段 Y 动得太狠，导致读谱失控？

三个问题都答得上来，谱子的定位就清楚了。

## 5. 数据口径与局限

- 时长取音频真实长度（`mutagen`），缺失时回落到"最后一个音符 - 第一个音符"
- `事件帧` 统计 `eventLayers[].*Events` 的关键帧总数（不含 `posControl`）
- `旋转线` 只统计**有效旋转**（|角度| > 0.001），排除编辑器写入的默认 0 帧
- `贴图` 排除默认 `line.png`，所以"0"代表"一张自制图都没有"
- 峰 NPS 用 1 秒滑动窗口，与游戏内实际手感会有 ±15% 偏差

后续如果样本增加到 20+ 张，建议按难度分级重算分位数，
本页的绝对数值只作**量级参考**，不要当成硬阈值。
