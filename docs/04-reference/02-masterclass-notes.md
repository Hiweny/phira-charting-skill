# 02 · 精品谱面拆解沉淀

> 三张大师级谱面 + 一张自己的实战案例。
> 每张都按"音乐 → 规模 → 舞台 → 编排 → 可迁移手法"拆。

---

## 一、《声嘶力竭》（カワキヲアメク）

- 谱师：ChuEN_cH
- 难度：IN Lv.13+
- BPM：129 · 542 拍 · 约 4:11
- 规模：**69 条判定线 / 1,861 音符 / 4.2 NPS**

### 1. 核心发现

**69 条线里只有约 15 条承载音符**，其余 54 条全是演员。
"判定线可以纯粹用来展示"——这张谱是这句话的标准答案。

### 2. 音符构成

| 类型 | 数量 | 占比 |
|---|---|---|
| Drag | 879 | **47.2%** |
| Tap | 811 | 43.6% |
| Hold | 95 | 5.1% |
| Flick | 76 | 4.1% |

X 坐标：范围 `[-450, 450]`，均值 `-10.6`（几乎中心对称），标准差 `257.7`（非常分散）。

> 启示：**Drag 可以是主力**。用大量 Drag 制造"洪流感"，而不是把 Drag 当点缀。

### 3. 线的角色分类（7 类）

| 类别 | 数量 | 角色 | 音符 |
|---|---|---|---|
| Main / Main-2/3/4 | 4 | 主判定 | 1,470 |
| drag-performance 系列 | 4 | Drag 专属表演 | 153 |
| actor1~19 | 19 | 纯视觉 | 169 |
| text*-up/left/down/right | 12 | 文字方框 | 8 |
| Rainline1~3 | 3 | 雨滴装饰 | **0** |
| words-* / dejavu-* | 5 | 歌词/文字 | 3 |
| Flick / Hold-* / HelpMe-* | 7 | 辅助 | 10 |

**演员线也有梯度**：actor1 有 279 moveX / 435 alpha，actor16~18 只有 3 个事件。
→ 前景密集、背景稀疏，才有层次。

### 4. 速度曲线（16 段，3 ~ 20）

| 拍 | 速度 | 意图 |
|---|---|---|
| 0 | 10 | 起速 |
| 27→31.5 | 10→20 | build-up |
| 31.75 | 7 | 骤降 |
| 74 | 9 | 微调 |
| 243 | 8 | 减速 |
| 500→501 | 9→12 | final drop |
| 504→512 | 12→3 | outro 拖尾 |

> 我们早期版本只有 8 段、最高 12——**速度曲线是情绪的过山车，不是手感参数**。

### 5. 父线家族（7 组）

- Main → HelpMe-Drag + Main-2/3/4
- dragperformance-fatherline → 4 条 Drag 表演线同步编舞
- text1~4-father → 各 4 条子线组成"可移动文字方框"
- flick-beginning → HelpMe-hold

父线事件少（4 个），子线事件多（110+）——**父管大局，子管细节**。

### 6. 特效

`extra.json`：1 个 BGA 视频 + 6 种着色器
`vignette`（全曲暗角）/ `chromatic`（build-up 色散）/ `grayscale`（低谷）/ `fisheye`（眩晕）等。

### 7. 可迁移手法

1. **大量演员线**（30~50 条）承载视觉，演奏线只留 2~4 条
2. **Drag 洪流**：Drag 占比可到 45%+
3. **演员线事件梯度**：主角线 200~400 事件，背景线 3~10 事件
4. **速度特写**：20 的极速 + 3 的拖尾
5. **父子线做"整体移动 + 各自旋转"**
6. **文字方框**：4 条子线围成框，父线移动

## 二、《Night Drawmers》

- 规模：**60 条线 / 约 1,800 音符 / 4 个分组**
- 哲学：**用着色器做动画**
- 纹理：8 张
- 自定义 GLSL：4 个（摄像机 / 雪花 / 炫光 / 液体）

### 1. 分组（4 组）

`Default / 黑线 / UI / 故事板`

### 2. 事件密度：每 1/8 拍

核心手法是**阻尼振荡**：判定线被音符"敲击"后抖动，振幅 `4.69 → 0` 指数衰减，每 1/8 拍一个关键帧。
我们的初版是"每 4~8 拍一个大事件"——密度差 20 倍以上。

### 3. 极端手段

- 速度 **999**，还有**负速度**（音符向上飞）
- BPM 变化：`164 → 1640（极端值）→ 164 → 158 → 120`
  → **音乐安静时用 BPM 制造混乱感**
- 音符位置：**离散 10~12 个固定点**（`-490/-368/-306/-184/-122/0/122/184/306/368/416/490`）
- **1/6 拍 Hold 链**：`1/6, 1/3, 1/2, 2/3, 5/6`，位置从右向中心移动
- **三线错峰加入**：Line 0 beat 19，Line 1 beat 145，Line 2 beat 147

### 4. attachUI：7 个元素全绑

`pause / combonumber / combo / score / bar / name / level`
→ UI 被判定线控制位置/透明度/旋转，实现"UI 与谱面融合"。

### 5. 可迁移手法

1. **阻尼振荡**（见 [`docs/03-workflow/03-judge-line-choreography.md`](../03-workflow/03-judge-line-choreography.md) §4.2）
2. **负速度 / 超高速**做奇观
3. **BPM 极端值**做"时间崩塌"
4. **1/6 拍细分**（不要只用 1/4、1/8、1/16）
5. **错峰加入**：线段不是同时出现，而是逐段加入，复杂度自然增长
6. **UI 绑定**做叙事

## 三、《浮生梦·探窗》

- 谱师：时辰shars
- 难度：IN Lv.11
- BPM：140
- 规模：**37 条线 / 9 个分组 / 355 音符 / 5 张纹理 / 7 条花瓣线 / 7,000+ 事件**
- 特效：**0 个 extra.json** —— 纯判定线动画

### 1. 核心发现

**每条花瓣线 1000+ 个事件，以 1/16 拍粒度逐帧更新。**
355 个音符撑起 37 条线的视觉盛宴。

> 如果说 Night Drawmers 是"用着色器做动画"，探窗就是"**用判定线做动画**"。

### 2. 九层分组

| # | 组名 | 线数 | 职能 |
|---|---|---|---|
| 0 | Default | 7 | 花瓣纹理 |
| 1 | 主线 | 2 | 演奏（141 + 221 notes） |
| 2 | 特效 | 2 | 文字方块 |
| 3 | 表演1 | 3 | 闪烁 |
| 4 | 表演2 | 3 | 扫描 |
| 5 | 表演1.1 | 3 | 另一组闪烁 |
| 6 | 特殊主线 | 2 | 倒置音符（各 16 notes） |
| 7 | 文字/图片 | 4 | 自定义纹理 |
| 8 | 表演3 | 3 | 渐隐 |

### 3. 花瓣系统（灵魂）

7 条花瓣线，纹理 `blossom1.png(126×126)` / `blossom.png(116×116)`：

| 线 | moveX | moveY | rotate | 起始 X | 起始 Y | 旋转 |
|---|---|---|---|---|---|---|
| 30 | 1005 | 1006 | 22 | +165 | 451 | 每 3 拍 180° |
| 31 | 1057 | 1058 | 1057 | -461 | 452 | 每 1/16 拍微调 |
| 32 | ~1000 | ~1000 | ~300 | -331 | ~450 | 每 3 拍 125° |
| 33 | ~1000 | ~1000 | ~300 | -660 | ~450 | 90°（反向） |
| 34 | ~1000 | ~1000 | ~300 | +67 | ~560 | 165° |
| 35 | ~1000 | ~1000 | ~300 | -543 | ~560 | 190° |
| 36 | ~1000 | ~1000 | ~300 | -121 | ~560 | 78° |

设计要点：
- 起始位置分散（X -660~+165，Y 450~560），避免重叠
- `alpha = 200` 半透明，柔和不抢戏
- 每条转速不同（78°~190°），自然
- **1/16 拍 = 人眼可感知平滑动画的最低粒度**

### 4. moveX 规律振荡

Line 0 在 beat 96~198 之间做 ±10 的振荡，**每 2 拍一个周期，持续 102 拍（约 51 个周期）**。
不是 1 个长事件，而是 51 个独立事件——这才是"逐帧动画"。

### 5. textEvents 的三种创意用法

| 用法 | 内容 | 效果 |
|---|---|---|
| 视觉标记 | `■` | 黑色方块定位 |
| 位置指示 | `▁` | 下划线标记特殊主线 |
| 感谢信 | 整段制谱感言 | 结尾全屏叙事 |

### 6. 学习到的新字段

`scaleXEvents` / `scaleYEvents`（纹理缩放）、`colorEvents`（颜色）、`gifEvents`（GIF）、
`rotateWithFather`（子线随父旋转）、`scaleOnNotes`（缩放是否影响音符）、`appearanceOnAttach`、`zIndex`。

### 7. 可迁移手法

1. **小纹理 + scale 放大 + 多条线组成粒子系统**
2. **1/16 拍逐帧动画**做平滑飘落
3. **规律振荡**（每 2 拍 ±10）替代单次位移
4. **起点分散 + alpha 半透明** = 自然的粒子群
5. **textEvents 做视觉标记**（Unicode 符号）
6. **零特效也能封神**——前提是线动画足够细

## 四、自己的实战案例：《Dangerous》（MJ）

- 谱师：Maid（本项目产出）
- BPM：112.35 · 75 小节 · 161.56s
- 规模：**6 条线 / 767 音符 / 2 个分组 / 5 个内置特效**

### 设计意图

用 note + 判定线"模拟 MJ 的舞蹈"，营造演唱会感：

| 线 | 角色 |
|---|---|
| MJ | 主判定 + 主表演（中央，随鼓点位移/旋转） |
| Left / Right | 左右副判定（对称） |
| Spotlight | 聚光灯扫射（纯表演） |
| Rhythm | 脉冲条（跟底鼓） |
| Special | 高潮特写（旋转炸开） |

### 踩过的坑（都在 PITFALLS 里）

- `id` 写成字符串
- Tap 缺 `endTime`
- 缺 `positionX`
- beat 三元组里写 `0.5`
- `isCover: false`
- control 字段写成 `{}`
- note 里多写 `tint` / `judgeArea`

### 现状与不足（诚实记录）

- ⚠️ **时间轴有致命错误**：初版把 beat 三元组当成 `[小节, 小节内拍, 0]`，导致
  - 分母出现 `0`（RPE 会除零）
  - 所有音符被压缩到歌曲前 1/4（161s 的歌只有前 40s 有 note）
  - 这是本项目最重要的教训，详见 PITFALLS **P13**
- ⚠️ 分组只有 2 个（对比探窗 9 个）
- ⚠️ 表演线事件密度不够（对比 1/8 拍）
- ⚠️ 特效偏"堆"而非"叙事"
- 重制方向：先用 `分` 重新换算时间轴（`beat = 小节*4 + 小节内拍`），再拆出 Performance/Texture/Text/UI 分组；Showcase 段做 1/8 拍律动

## 六、三张谱给我们的统一结论

1. **演奏线要少（2~4 条），演员线要多（10~50 条）**。
2. **事件密度决定"专业感"**：1/8 ~ 1/16 拍是门槛。
3. **特效与线动画是两条路，都能封神，但别混着乱用**。
4. **分组命名就是设计文档**。
5. **速度/BPM 是情绪工具**，不只是手感参数。
6. **留白比堆满更高级**（探窗 355 音符 vs 声嘶力竭 1861 音符，各有千秋）。
