# 案例拆解：《深圳东》

> 谱面：`3944639778176848.json`（RPE） / 曲长 289.8 s / 159.99 BPM / **AT Lv.15.9**
> 53 条判定线 / **2431 个真 note，0 假 note** / `extra.json` 自带 8 类 shader
> 类型：Tap 1586 · Drag 509 · Hold 194 · Flick 142
> 谱面文件本身**没有任何 colorEvents / tint**——它的"颜色"来自皮肤、note 类型和 shader 三层叠加。

这是一张"高强度观赏谱"：读谱压力大，但画面、节奏互动、情绪结构都极完整。
它最值得学的不是某个 pattern，而是**把颜色、速度、线框、留白当成同一支乐队来指挥**。

## 1.5 视觉观察（逐帧，不是从 JSON 推的）

> 数据只能回答"用了什么"，画面才能回答"为什么好看"。
> 用对齐后的预览器在这些时间点抽帧：
>
> ```bash
> python3 tools/preview_render.py /workspace/ref/shenzhendong \
>   --contact-sheet _qc/sheet_visual.png \
>   --times 0.5,6,12.2,18,36,60,94,105,126,132,145.5,152,176,184,199.5,207,214,220,240,246,250.5,262.5,266,280
> ```
>
> 产出 `<谱面目录>/_qc/sheet_visual.png`。下面每一条都是**看到**的，不是猜的。

### A. 明度分层：背景 < 线 < note

- 背景是暗色插画 + 巨大汉字水印，`backgroundDim=0.6`，实际明度压得很低；
- 判定线是暖白（默认 `color_perfect`），比背景亮一档，但**不抢**；
- note 是高饱和蓝 / 黄 / 红，最亮。
- 所以即使高潮有 30+ 条线交叉，note 依然读得出来。
  **读谱清晰度不是靠"少放线"，而是靠亮度分层 + note 高饱和。**

### B. 线是"长曝光"，不是短线

- `lineLength=6` 让每条线有 6 个屏幕高；旋转后就是贯穿全屏的斜线；
- 几十条这样的线同时存在，画面是一张不断变形的**三角 / 菱形网格**；
- 网格密度随段落走：前奏几乎空 → 副歌中心柱 → 高潮满屏网格 → 终章收成一颗星。
- 只看 JSON 会以为"53 条线太多"，看画面才知道它们大部分时间是**稀疏的几何骨架**。

### C. 两态在画面上真的一眼可分

- **中心柱**：note 全落在一条窄到几乎为零的竖带（x=0），斜线只是穿过它；
- **全屏散开**：note 横向铺到 ±540，线框打开成大三角 / 大菱形；
- 切换点都在强拍。观众记住的是"柱 → 散 → 柱"的呼吸，不是某一个 note。

### D. 颜色是"信号"，不是装饰

- 蓝 Tap 占 65%（1586/2431），是底色；
- 黄 Drag 只在需要"横向划"时成排出现（12.2 s 的 158 连、240 s 的蛇形）；
- **红 Flick 极少**，集中在 176–187 s 的左右对打——红色一出现就是"这里要甩"；
- 白 Hold 在 199.5 s 附近竖成光柱，是画面里唯一的"实体"。
- 结论：颜色节奏 = **让稀有颜色只在关键段出现**，而不是全曲平均分配。

### E. 留白是"撤物量 + 压暗角"，不是黑屏

- 94 s：`circleBlur` 让中心爆出一团白光，像镜头呼吸；
- 105 s / 132 s：`vignette` 把四周压黑，只剩中心几根线和 note；
- 262.5 s：几乎全黑，只留一颗交叉星，**整整 2 秒没有 note**；
- 266 s：`glitch` 把 RGB 撕开，叠在残存网格上——"信号坏了"。
- 只看数据，留白段只是"物量 0"；看画面才知道**空得有层次**。

### G. 复现时怎么"看"

1. 先抽 24 帧联系表，确认两态、颜色、留白都成立；
2. 对不合格的段落再抽 60 fps 视频，看轨迹、闪烁、速度脉冲；
3. 每次只看三件事：**note 有没有被线压住、相邻帧是不是同构图、留白段还有没有东西看**；
4. 预览器没有皮肤和粒子，但足以抓出 80% 的构图问题；剩下 20% 交真机。

## 2. 颜色课：颜色不靠 colorEvents，靠三层叠加

### 2.1 第一层：皮肤色盘（默认 respack 的真实 RGB）

| 类型 | 贴图 | 主色 |
|---|---|---|
| Tap | `click.png` 998×100 | `(75,160,229)` 蓝 |
| Hold | `hold.png` 1000×1100 | `(228,238,250)` 近白 |
| Drag | `drag.png` 948×50 | `(228,196,66)` 黄 |
| Flick | `flick.png` 998×172 | `(213,30,30)` 红 |

所以"颜色节奏"最便宜的做法是**换 note 类型**：
蓝色 Tap 打底、黄色 Drag 画横线、红色 Flick 点重音、近白 Hold 拉出光柱。
这张谱 60–84 s 全是蓝、176–187 s 突然换成红色对打，**颜色变化本身就是段落变化**。

### 2.2 第二层：shader 把颜色当打击乐

`extra.json` 的 `effects` 全部按 **beat 三元组**定时，和音符同一套时间系统：

| 时间 | 效果 | 作用 |
|---|---|---|
| 0–12.19 s | `grayscale` | 前奏全灰，像旧照片 |
| 12.19–22.5 s | `grayscale` ↔ `chromatic` 交替 6 次 | 灰/彩对切，每次切在乐句重音上 |
| 93.76–95.82 s | `circleBlur`（size 1→5） | 光晕膨胀，接副歌 |
| 95.82–96.01 s | `chromatic` 0.19 s | 入副歌的"闪光" |
| 96–117.4 s | `vignette` | 四周压黑，视线锁中心柱 |
| 120–131.63 s | **16 次 `chromatic`，每 2 拍一次** | 越来越急的"彩色心跳"，推向 132 s 断点 |
| 132–139.5 s | `vignette` | 留白段，画面几乎只剩中心 |
| 250.5–262.5 s | `vignette` | 尾段收束 |
| 262.5–270.4 s | `glitch` ×4 | 终章"信号损坏"，正好盖住空拍 |

**手法名：灰阶—色差对切（grayscale/chromatic call-and-response）。**
执行要点：
- 对切必须卡在**乐句边界**，不要按固定间隔乱闪；
- `chromatic` 默认 `power=0.01`，只做轻微 RGB 分离，别调大；
- 断点前用"间隔减半"的闪频制造加速感（这张谱固定 2 拍，靠 BPM 本身推进）；
- `vignette` 是"消音器"：留白段压暗四周，比直接黑屏高级。

> 玩家若开 `NO_SHADER` 模组，所有效果会被清空。**不能把可读性、判定信息放进 shader**，
> 只让它做情绪和色彩。

### 2.3 第三层：插画与 dim

`info.yml` 的 `backgroundDim=0.6` 让插画退到背景；亮色 note 才跳得出来。
这张谱的背景图本身有巨大的"深圳东"字样，线框与文字同构，**背景即舞台布景**。

## 3. 节奏交互课：让"打"本身有形状

### 3.1 双线对打（L5 + L6）

36–60 s，两条线都停在 `(0,-300)`，旋转 `±5°`，各 64 个 Tap，时间几乎一一对应。
视觉上是"两条几乎重合的线微微分叉"，手上是**双押/交替**。
> 这叫**双线对打**：不用两条线拉很远，微错位反而更高级。

### 3.2 镜像对打（L33 + L46）

204–214 s，两条线分别把 note 放在 `+135 / -135`，每个时间点左右各一个：

```
207.01 s  (+135,-135)
207.76 s  (+135,-135)
...
211.14 s  ... 间隔 0.19 s（半拍）
212.26 s  ... 间隔 0.09 s（16 分）
```

**固定音高、只缩间隔** = 密度递增。玩家的手会自然加速，这是最有效的"难度爬坡"。

### 3.3 Flick 对打（L32）

176–187 s，58 个 Flick 全在 `±405`，每 0.75 s 一对，中间夹 16 分双 flick。
红色箭头在左右两侧同时亮起，**颜色 + 方向 + 镜像**三件事一起说"这里要甩"。

### 3.4 四线收束（L10–L13）

140–152 s 的四条线，`moveX` 轨迹精确到像素：

```
132.0 s   L10 -700 → 300    L11 -900 → 100
          L12 -1100 → -100  L13 -1300 → -300
136.5 s   四条线停在 300 / 100 / -100 / -300
145.5 s   同时收到 0
```

每条线的 note 都在 `x=0`，所以 **note 跟着线一起从两侧扫入、再合拢到中心**。
线在 0–132 s 一直停在 `x=114514`（屏幕外）——**"114514 隐藏法"**。

### 3.5 中心柱 ↔ 全屏散开（两态切换）

- L9：588 个 note，`x=0`，`speed=10`，速度事件只有 1 条（恒定）；
- L18：705 个 note，`x=0`，speed 10→12→9→**-4（倒流 0.75 s）**→8→18→30→9；
- L19：322 个 note，`x=-450..450`，`y=-300..700`，承担全屏散开。

> `speed` 在这里不是"下落快慢"，而是**画面节奏**：
> 199.5 s 突然 `-4`，整柱 note 反向倒流 0.75 s，像倒吸一口气；
> 213–214 s 连续 `18→-1→30→19`，是"速度抖动"重音。
> 这叫**速度脉冲（speed punch）**。

### 3.6 叠音（117 处完全重叠）

把 2–5 个同时间/同位置/同类型的 note 叠在一起，判定只算一次（或按引擎规则），
但**视觉厚度翻倍**。L1 有 16 处叠音，用来把关键拍做"加粗"。
> 这是纯视觉手法；不要全曲滥用，只在重音用。

## 4. 判定线表演课：用"线框"造空间

这张谱 **`inclineEvents` 全是 0**，3D 感不来自倾斜，而来自**长线 + 多线交叉 + 共点 + 速度**。

### 4.1 线有多长？

`info.yml: lineLength = 6.0`。prpr 里普通线从 `-lineLength` 画到 `+lineLength`，
**总长 12 个世界单位**（世界半高=1），即 6 个屏幕高度。
所以一条线旋转 30°，看起来就像一道贯穿屏幕的激光——这是"线框空间"的物理基础。

### 4.2 共点星芒（六星芒的正确做法）

214 s 附近，L28/L29/L30 三条线全部平移 `(0,0)`，旋转 `-60° / -120° / -180°`。
三条线过同一点、每 60° 一条 → 屏幕上就是 **6 条射线 = 六星芒**。
比用 6 条线各画一条更省线，而且旋转任意一条整颗星都会"呼吸"。

同理，L47–L52 在结尾分成两组，每组三条线 `0°/-60°/-120°`，
分别锚在 `(-350,-250)` 和 `(350,-250)`——**两侧各一颗星**。

### 4.3 角射线（L20–L27）

226 s 附近，8 条线锚在四个角 `(±550, ±350)`，旋转 `-85° / -175°`，
从四角向中心射出——像舞台四角的探照灯，把画面框成一个"房间"。

### 4.4 隐藏线的三种方法

1. `moveX = 114514`（最常用，编辑器里"扔出屏幕"）；
2. `moveY = ±1000`（扔到屏幕外）；
3. `alpha = 0`（但 note 仍会显示、仍判定，容易出"幽灵 note"）。

> `alpha` 为负数在 Phira 的 RPE 解析里会被 `max(0)`（`pe_alpha_extension=false`），
> **不能**用 Phigros 的负 alpha 扩展来做"隐藏线/提前显示"。

### 4.5 线接力（line relay）

全曲有 16 条线真正承载 note，但**同一时刻最多两条**：

```
L2 → L5+L6 → L9 → L0/L1/L31 → L10-13 → L18 → L32 → L19 → L43 → L47-52
```

上一段结束后，线要么被扔到 114514，要么 alpha 归零；下一段换一条新线。
**这就是"只保留一条演奏线"在长曲里的正确实现：不是一条线用到底，而是接力。**

## 5. 音画同步的 10 个瞬间

1. **0–12 s** 全灰、无 note，只有插画和两条 hold 的微光——"雨还没下"。
2. **12.19 s** 第一下彩色闪，158 个 Drag 同时开始——"颜色先于音符到达"。
3. **36 s** 双线在中心微微分叉，Tap 双押开始。
4. **60 s** 中心柱出现，L9 把 588 个 note 钉在 x=0。
5. **93.76 s** circleBlur 光晕膨胀，95.8 s 色差闪一下 → 副歌。
6. **96 s** vignette 压暗，世界只剩中间一条柱。
7. **120–131.6 s** 色差每 2 拍闪一次，像心跳加速；132 s 音乐断，物量掉到 0.9/s。
8. **140–145.5 s** 四条线从 ±1300 扫入并合拢，note 跟着线走——"四面合围"。
9. **199.5 s** 速度瞬间 -4，中心柱倒流 0.75 s——"倒吸一口气"。
10. **262.5–270.4 s** glitch 四连击盖住空拍，最后 8 个 Drag 从两侧星芒落下。

## 6. 单线移植配方（仍守"一条演奏线"）

想把《深圳东》的手法搬进自己的谱，按这个顺序：

1. **先定两种态**：中心柱（`x=0`、`speed≈10`）和全屏散开（`x∈[-450,450]`）。
   每个大段落只选一种，不要混。
2. **线接力**：每段用一条新线；旧线 `moveX→114514` 或 `alpha→0`。
3. **用 note 类型调色**：蓝 Tap 打底，黄 Drag 画横线/蛇形，红 Flick 点重音，白 Hold 拉光柱。
4. **shader 只做情绪**：前奏 grayscale，副歌前 chromatic 加速，留白 vignette，终章 glitch。
   全部按 beat 写，卡乐句边界。
5. **高潮加一颗共点星**：3 条线同点、`-60°/-120°/-180°`；整段只转其中一条。
6. **速度写 2–3 个脉冲**：`10→-4→10` 或 `8→18→30→9`，只在重音。
7. **留白**：至少 4–8 秒物量 < 1/s，配 vignette；这比堆满更难忘。

- [ ] 旧线已隐藏（位置/alpha），没有"幽灵线"；
- [ ] 中心柱的 `positionX` 真的是 0，速度事件 ≤ 3 条；
- [ ] Flick 对打左右位置对称、时间成对；
- [ ] 密度递增只缩间隔、不改音高；
- [ ] shader 时间用 beat 三元组，切点落在乐句；
- [ ] 全曲至少一次"物量骤降 + vignette"的留白；
- [ ] 高潮有一颗共点星芒或四角射线；
- [ ] 没有把判定信息（可读性）交给 shader；
- [ ] 在真机/预览器里逐段看联系表，确认"两态"一眼能分清。

---

## 8. 坑

1. **`multiLineString` / `multiScale` 是 RPE 专有字段，Phira 直接忽略**，不要依赖。
2. **`skewControl` 也被忽略**（prpr 未实现），斜切不会生效。
3. **`above=2` 在 Phira 的 RPE 解析里不影响下落方向**，也不会把 note 翻面；
   不要用它做"反向雨"。
4. **负 speed 才是反向**（`∫speed dt` 为负 → note 在线的另一侧）。
5. **`alphaControl/sizeControl/posControl/yControl` 是按 note 行进距离求值的**，
   不是按时间，也不是线的属性。用它们做"距离雾/透视缩放/扇阵收放"。
6. **线太长会盖住 note**：`lineLength` 默认 6，配合 `zOrder` 和 alpha 控制层级。
7. **`114514` 不是魔法数字，只是"足够远"**；换成 99999 也一样。
8. **shader 会被 `NO_SHADER` 模组清空**，颜色设计必须有"无 shader 也成立"的底稿。
9. **叠音不要超过 5 层**，否则打击特效糊成一团。
10. **视频线需要 `video` feature**（官方 release 默认开启），自编译要确认。

---

## 9. 一句话总结

《时落之雨》教的是"线即轨迹、note 拟物"；
《深圳东》教的是**"把颜色、速度、线框、留白当成乐器来编曲"**——
它的高级感来自**结构**：两态、接力、留白、加速闪频，
而不是某个单独的花招。
