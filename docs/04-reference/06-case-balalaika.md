# 案例二：《巴拉莱卡》— 零素材的几何演出

> 与《enchanted love》是两个极端：
> 前者花 100 张自制贴图，这张**一张都没用**，却拿到 147.5 帧/秒（样本最高）。
> 它证明：**动画感不一定来自素材，可以来自运动本身。**

- 谱面 ID：`55018518`｜难度 IN Lv.15（`difficulty: 15.4`）
- 作者：兮梦 Feat.YS的拳头｜署名版本："三版"
- 编辑时长：`EditTime` 52 353 s ≈ **14.5 小时**

## 2. 骨架：3 条打击线 + 40 条演出线

| 线 | 音符 | 角色 |
|---|---|---|
| L0 | **457** | 主打击线 |
| L1 | **559** | 副打击线（带 `scaleX/scaleY`） |
| L2 | 152 | 过渡打击线 |
| L3–L29 | 各 ~2 | 基本闲置（占位） |
| L30–L37 | 各 2 | **纯演出线**，moveX 在 ±750 之间扫射 |

**88% 的音符挤在 3 条线上。** 这和《enchanted love》"24 条演奏线分段轮换"是
完全相反的策略：

- 少线 → 读谱稳定、手感连贯，适合技术向
- 多线 → 每段可以就地换构图，适合演出向

演出线的手法很朴素：

```
moveX 从 0 突进到 ±700（2~7 拍内完成）
alpha 事件只有 3 个：(0,0) → (0,150) → (150,0)
即"闪现 → 停留 → 消失"，没有淡入淡出
```

这就是几何谱的语言：**硬切、扫射、闪现**，不做柔和过渡。

## 3. 时间结构：25 秒吃掉一半工作量

| 区段 | 帧数/10s | 事件 |
|---|---|---|
| 0–20 s | 4 512 + 3 093 | 开场演出（音符很少） |
| 20–50 s | 336 ~ 433 | 铺主歌 |
| 50–70 s | 2 000 + 1 511 | 第一次副歌 |
| 70–150 s | 112 ~ 569 | 谱面为主，演出克制 |
| **150–175 s** | **4 829 / 9 305 / 3 121** | **大高潮，占全谱 52%** |

结论：**高潮段一次性投 17 000 帧**，前后两段保持克制。
这不是"均匀好看"，是**集中火力**。

## 4. 视频层（`extra.json` 的 `videos`）

这是本谱最值得抄的结构：**视频是独立图层，不占用判定线**。

```json
{
  "path": "bga1.mp4",
  "time": [386, 0, 1],
  "scale": "cropCenter",
  "alpha": 0.5,
  "dim": 0.3,
  "startTime": [0, 0, 1],
  "endTime": [18, 0, 1],
  "easingType": 1,
  "offsetX": 2, "offsetY": 0,
  "colorFilter": [0.0, 0.0, 1.0, 1.0]
}
```

实测解读：

| 字段 | 值 | 含义 |
|---|---|---|
| `path` | `bga1.mp4` | 与谱同目录；实测 480×480 / 30 fps / 18.44 s |
| `time` | `[386,0,1]` | 起始位置 = 第 386 拍 ≈ **197.9 s**（117 BPM） |
| `startTime` / `endTime` | `[0,0,1]` / `[18,0,1]` | 视频内裁切窗口，单位是**秒**（18 与 18.44 s 吻合） |
| `scale` | `cropCenter` | 裁切铺满，不拉伸变形 |
| `alpha` | 0.5 | 半透明叠加，不抢谱面 |
| `dim` | 0.3 | 额外压暗 |
| `colorFilter` | `[0,0,1,1]` | **蓝色染色**，把视频统一进冷色调 |

可操作建议：

- 视频**永远半透明**（`alpha ≤ 0.6` + `dim ≥ 0.2`），否则高速段读谱必崩
- 用 `colorFilter` 做**调色统一**，比重新剪视频便宜得多
- 视频放**弱谱区**（本例 197.9 s 处音符很稀），别和爆发段抢注意力
- 480×480 就够用，`cropCenter` 会自动适配 16:9

> 注意：`videos` 是 RPE 1.6 的扩展字段，Phira 各版本支持度不一。
> 发布前务必在目标客户端实测一次。

## 5. `multiLineString`：不是特效，是默认字段

本谱顶层有：

```json
"multiLineString": "1 2 3 5",
"multiScale": 0.458
```

我一开始猜它是"把一条线画成线阵"的隐藏开关。**后来取样 18 张谱，18 张都有这两个字段**，
值还各不相同（与本谱画面无关）——所以它是 **RPE 保存时写入的默认字段**，
不是本谱的特殊手法。

教训写在这里：**单个样本上的"独特字段"，先做频率统计再下结论。**

> 仍在待验证范围的只有：客户端是否真的会用 `multiScale` 改变线条渲染。
> 如果要用，必须先在目标客户端截图确认。

## 6. 音符构成：Tap 主导的技术向

| 类型 | 占比 | 说明 |
|---|---|---|
| Tap | **56%** | 高速定位为主 |
| Drag | **23%** | 铺密度、连段 |
| Hold | **16%** | 长音呼吸 |
| Flick | **4%** | 只在重音处点一下 |

和爆发向谱面（探窗 Drag 54%、声嘶力竭 Drag 47%、83844 Drag 86%）比，
这张的 Drag 明显少——因为它要的是**每颗都得对准的定位压力**：

- 技术向谱面靠 Tap 撑密度，Drag 一多判定就变松
- Flick 全谱只 63 个，都压在重音上，不参与铺量
- 峰 NPS 48 已经很高，再堆 Drag 会变成"手指放上去就行"

对应到 [05-cross-chart-benchmarks §2.1](05-cross-chart-benchmarks.md)：
**Tap / Drag 的比例按风格定，不按难度定。**

## 7. 施工图（想复刻 D 档就照这个顺序）

1. **先定打击线**：2~3 条，承载 85% 以上音符，位置固定在舒适区
2. **再定演出线**：30~40 条，全部 `line.png`，zOrder 分层
3. **写闪现语法**：alpha 三帧（0→150→0），moveX 突进 ±700，2~7 拍完成
4. **集中火力**：全谱只做 2~3 个大高潮，每段投 5 000+ 帧
5. **中段克制**：非高潮区帧/秒压到 20 以下，让画面"呼吸"
6. **视频层可选**：弱谱区插 15~20 秒 BGA，`alpha` 0.5 + `colorFilter` 调色
7. **最后跑自检**：`chart_stats.py` 看帧/秒是否 100+、`preview_render.py` 看构图

## 8. 代价与风险

| 维度 | 事实 | 建议 |
|---|---|---|
| 性能 | 33 226 帧、同屏可达 40 线 | 手机端先测；演出线别全开 `isCover: 0` |
| 可读性 | 线阵扫射易糊 | 演出线 alpha 峰值 ≤ 180，别压过 note |
| 素材 | 零贴图 | 优点是零成本，缺点是**换个曲子会显得雷同** |
| 复用 | 运动语法可复用，具体编排不可 | 把"闪现+扫射"做成函数，别复制 JSON |
| 视频 | 依赖客户端支持 | 必须有降级方案（无视频时谱面仍完整） |
| 迭代 | 作者做了"三版" | 演出向谱面几乎都要重做 2~3 次，预算要留够 |

> 一句话：**《巴拉莱卡》证明"没有素材也能做出动画感"，
> 但也证明"几何演出"的钱全花在运动设计上——省了美术，省不了脑子。**
