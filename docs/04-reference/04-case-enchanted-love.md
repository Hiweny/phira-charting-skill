# 04 · 案例拆解：《enchanted love》— 把谱面做成舞台剧

> 来源：Phira 社区下载（本地学习用，不二次分发）。
> 这是本项目目前遇到的**最接近"动画作品"**的谱面：全曲没有使用任何 shader，
> 只用 **287 条图片判定线 + 101 张自绘贴图**，做出了 2 分 21 秒的完整绘本动画。

---

## 1. 体量与成本（先看数字）

| 项 | 值 |
|---|---|
| 时长 / BPM | 音频 141.5 s，音符止于 114.9 s；BPM 95 恒定，无变速 |
| 判定线总数 | **287** |
| 贴图线（有 `Texture`） | **287（占 100%）** |
| 不同贴图文件 | **101**（另有 26 张字母图） |
| 音符总数 | **700**（Tap 311 / Flick 214 / Drag 123 / Hold 52） |
| 平均 / 峰值 NPS | 6.09（音符段）/ **22**（1 秒滑窗） |
| 事件关键帧总数 | **14 187**（平均每条线 49 个） |
| 扩展事件 | colorEvents 286 条线；scaleX/scaleY 256 条线；`inclineEvents` 虽普遍存在但**值全为 0**（未用 3D） |
| extra.json / shader | **无**（0 特效） |
| 作者编辑时长 | `chartTime` = 519 956 s ≈ **144 小时**（intro 自述做了一个月） |
| 曲绘 | 1 张 1350×900，与谱面内舞台完全同构 |

**结论一：这不是"加了点特效的谱"，而是一部用谱面格式做的动画片。**
音符只占工作量的 5%，其余 95% 是舞台、角色、转场、字幕。

## 2. 音乐分析（先听懂再拆谱）

| 段 | 时间 | 内容 | tension | brightness | 谱面在这一段做什么 |
|---|---|---|---|---|---|
| 1 | 0:00–0:02 | 环境音起 | 0.1 | 0.2 | 黑屏 → 聚光灯亮起 |
| 2 | 0:02–0:22 | 人声进入，轻鼓 | 0.3 | 0.5 | **零音符**，只有舞台与角色呼吸 |
| 3 | 0:22–0:58 | 主歌推进 | 0.4 | 0.6 | 音符进入（12s 起），角色小幅动作 |
| 4 | 0:58–1:02 | 短促过渡 | 0.6 | 0.7 | 全屏纯色闪（转场） |
| 5 | 1:02–1:38 | 副歌 | 0.8 | 0.85 | 舞台倾斜、条纹扫屏、鱼群、救生圈旋转 |
| 6 | 1:38–2:08 | 二次副歌/发展 | 0.9 | 0.9 | 元素密度峰值（95–105s 新增 108 个贴图） |
| 7 | 2:08–2:16 | 抽离 | 0.3 | 0.6 | 只剩光束与剪影 |
| 8 | 2:16–2:21 | 收尾 | 0.15 | 0.5 | 回到开场舞台 + "Thanks for playing" |

**关键观察**：
- 前 12 秒**一个音符都没有**，但事件关键帧 0–4s 就有 2433 个。
  → **开场用来"建立世界"，不用来"考手速"**。
- 音符密度峰值与视觉元素密度峰值**同时出现**（95–105s），
  但二者**不在同一条线**：音符在贴图上层的细线，视觉在底层铺满。
- 结尾回到开场构图（首尾呼应），音乐收束时视觉也收束。

## 3. 谱面骨架：三层系统

这张谱把 287 条线严格分工，互不干扰：

| 层 | 线数 | 职责 | 识别特征 |
|---|---|---|---|
| **舞台层** | 21 | 永远可见的布景与角色 | `alphaEvents` 全 0 占位（= 未设置，恒可见） |
| **演出层** | 266 | 按秒表出场的贴图 | 真实 alpha 0→255→0 的"进出场"曲线 |
| **演奏层** | 24 | 承载 700 个音符 | `Texture: line.png`，`isCover: 1` |

> **可复用原则**：先分"永远在的"与"按需出现的"，再分"负责打的"。
> 三层混在一起，谱面一定会乱。

### 3.1 舞台层：固定剧团的站位

开场的角色不是整体一张图，而是**逐个部件**摆在一条 `ground line` 上：

```
鸭子(duck)   救生圈(Volleyball/Circle)   少女(Window)   青蛙王子(frog.prince)   沙滩球
        └────────────── 地面横线 line.png ──────────────┘
                    标题 enchanted love（字母拼装）
```

角色本身也是部件化的：`frog.prince_on.water.png` + `frog.prince_on.water_shadow.png`、
`fish.head_in.water.png` + `fish.body_in.water.png`、`heart_head/body/end.png`。

**为什么拆部件**：拆开才能让每个部件独立位移/缩放/染色，
例如青蛙点头只需动 head，鱼游动只需 head 与 body 错相位。

### 3.2 演出层：秒表式出场

266 条贴图线的 alpha 曲线形态高度一致：

```
alpha
255 ┤        ┌────────────┐
    │        │            │
  0 ┤────────┘            └────────
    └────┬────┬────────────┬──────→ t
       入场  停留          退场
```

这是本谱最重要的工程规律：**每个元素都有明确的"上场/停留/下场"三段**，
没有"突然出现"也没有"忘了关掉"。

统计每 5 秒"新上场"的元素数量，可以直接读出转场节点：

```
0s:3   5s:17  10s:26 15s:9  20s:28 25s:19 30s:17 35s:4  40s:12 45s:8
50s:23 55s:31 60s:5  65s:15 70s:14 75s:4  80s:2  85s:27 90s:36 95s:72
100s:36 105s:6 120s:4 125s:42 130s:14 135s:3
```

三个峰值：`95s`（副歌总爆发 72 个）、`125s`（终章换景 42 个）、`55s`（31 个）。

### 3.3 演奏层：收窄的战场

- 音符 x 范围只有 **[-440, 440]**（不是 ±675）
  → 因为舞台主体（绿色三角）只有这么宽，note 超出就会压到角色身上。
- 演奏线用 `line.png`，`isCover: 1`（全谱统一）→ 音符到达线即消失，手感干脆。
- 24 条演奏线**按段落轮换**：`L0` 承 12–141s、`L8` 承 0–33s、`L16` 承 53–88s……
  不是"一条线打全曲"，而是每个段落换一组（方便就地做局部演出）。

## 4. 核心技术：图片判定线 = 精灵图层

这是本谱的全部魔法，字段级拆解：

| 字段 | 作用 | 本谱用法 |
|---|---|---|
| `Texture` | 指定 PNG | 101 种贴图，文件名带像素宽（`Block.x800.png` = 800px） |
| `anchor` | 锚点（0~1） | 默认 `[0.5,0.5]`，用于绕中心旋转/缩放 |
| `zOrder` | 图层顺序 | 同 z 时按数组顺序绘制；背景负值、前景正值 |
| `isCover` | 音符越过判定线后是否继续绘制 | 全谱 287 条都是 1 → 音符到线即消失 |
| `eventLayers[].alphaEvents` | 进出场 | 0~255，两帧阶跃即"闪现"，长段插值即"淡入" |
| `eventLayers[].moveX/moveY` | 位移 | 常配合 `x=±1800` 做"停靠在画外" |
| `eventLayers[].rotateEvents` | 旋转 | 整个舞台倾斜、道具自转 |
| `extended.scaleXEvents/scaleYEvents` | 非等比缩放 | 拍扁/拉长、呼吸感 |
| `extended.colorEvents` | **染色** | 白底贴图 + 染色 = 无限配色（本谱主色 `[241,243,190]` 奶油 / `[0,197,156]` 青绿） |
| `extended.inclineEvents` | 倾斜剪切 | 透视感、跑动感 |
| `extended.gifEvents` / `isGif` | GIF 序列 | 本谱基本弃用（作者自述因内存问题优化掉一半 GIF） |

### 4.1 为什么用"白图 + 染色"

101 张贴图里绝大多数是**纯白剪影**。颜色全部交给 `colorEvents`：

```
同一条线的 colorEvents 可以在 3 秒内从 奶油 → 青绿 → 深蓝
= 一次"换色转场"，零额外资源、零额外线
```

这比"每个颜色存一张图"省 10 倍资源，也是这套系统能塞进手机的关键。

### 4.2 画外停靠（本谱最常用的运镜）

道具平时停在 `x = ±1800`（屏幕外），需要时用 `moveX` 扫进来：

```
moveX: 1800 → 0（0.4s, easing 2）→ 停留 → 0 → -1800
```

好处：
- 不需要新增/删除线，**一条线可以反复用整曲**
- "从画外飞入"天然带有方向感与速度感
- 拉远/推近只需改 `scale`，不必重排

## 5. 转场语法（这张谱的"剪辑"）

把联系表按时间排开，可归纳出 5 种可复用的转场：

| 转场 | 做法 | 效果 | 用在 |
|---|---|---|---|
| **光圈开合（iris）** | 超大圆形贴图 `Circle.x1600` 缩放 0→3，或用"遮罩环"由小到大 | 镜头推进/拉远，章节切换 | 30s、40s |
| **全屏闪色** | 一张纯色 `big_square.x2400` 全屏 alpha 0→255→0（3 帧） | 硬切，段落断开 | 58s |
| **条纹扫过** | 斜条纹贴图横向扫过 + 全屏轻微倾斜 | 速度感，进入副歌 | 71s |
| **整体倾斜/旋转** | 父线 `rotateEvents` 带动全部子线 | 世界失衡 | 副歌、终章 |
| **光柱显现** | 竖直渐变贴图 scaling + 角色剪影 | 升华、告别 | 127s |

> **规律**：转场永远发生在**音乐的结构边界**（段落交界、静音前后），
> 而不是"差不多这里换一下"。

## 6. 文字系统（Phira 没有文字事件）

这张谱要显示标题、副标题、结语，用了两套办法：

### 6.1 字母拼装

26 条 `letter_*.pn` 线，每个字母一个图层，手动摆位拼出 `enchanted love`。
- 每个字母有 `letter_x.png`（填充）+ `letter_x_stroke.png`（描边）两层
- 好处：每个字可以独立跳动、错峰入场
- 代价：一个词要 8~14 条线，改字要重摆

### 6.2 多色变体 + alpha 切色

`text_color.palette.00c59b.png`、`.f1f3be.png`、`.ff6460.png`……
同一段文字准备了 8 个配色版本，**同位置、同 z，靠 alpha 的 255/0 切换**：

```
版本 A: 0 ──255──────0
版本 B: 0 ──────255──────0
版本 C: 0 ──────────255──────0
```

同一时刻只有一层不透明，视觉上就是"文字变色"。

> 更强的做法（本谱没用到）：`colorEvents` 直接染白字贴图，一行搞定渐变变色。
> 需要"每个字不同色"才需要多版本。

## 8. 代价与风险（必须一起学）

| 问题 | 本谱的表现 | 教训 |
|---|---|---|
| 内存 | 作者自述"规模过大导致 Phira 内存问题，优化掉一半 GIF" | 贴图别超 100 张，单张别超 1000px，慎用 GIF |
| 性能 | 287 线 × 平均 49 关键帧 | 手机掉帧风险高；同屏可见线建议 ≤ 40 |
| 制作 | 144 小时 | 动画谱不是"加特效"，是"做片子"，要按镜头语言规划 |
| 可移植 | 贴图与坐标强绑定 | 换个曲绘就全废；不可复用为模板，只能复用方法 |
| 难度 | 平均 6.09 NPS，峰值 22；Flick 占 31% | 视觉极重但手感偏轻，属于"观赏向" |

> **不要因为好看就学它堆 287 条线。**
> 学会的是：分层、进出场、转场、染色、画外停靠。线数是结果，不是目标。

## 9. 如果你要做一张同类的（最小可行版本）

```text
1. 定舞台：一张底图（聚光灯/房间/海面） + 一条地面线
2. 选角色：3~5 个，每个拆 2~3 个部件（头/身/影）
3. 做 5 个母题动作：呼吸、点头、漂浮、旋转、消失
4. 排 4 个转场：iris / 闪色 / 条纹 / 倾斜
5. 文字：标题用字母拼装（≤10 字），颜色用 colorEvents
6. 演奏线：单独 1~2 条 line.png，isCover=1，x 收窄到舞台宽
7. 音符：只在音乐有"明确事件"的地方放，其余留给画面
8. 总线段控制在 60~80 条（本谱 287 是极限，不是起点）
```

## 10. 十条沉淀

1. **谱面可以是"没有主角的动画"**：700 个音符撑不起 141 秒，舞台可以。
2. **先分层，再画**：永远可见 / 按需出场 / 承载音符，三者物理隔离。
3. **白图 + 染色**是性价比之王：一张图配 `colorEvents` 顶十张图。
4. **画外停靠**让一条线复用整曲，是"运镜"的基础。
5. **每个元素都要有下场**；忘记关 alpha 的贴图会糊在画面上。
6. **转场必须踩结构边界**，不能"感觉这里该换了"。
7. **`isCover=1`** 是动画谱的安全带：保证 note 永远不被布景吃掉。
8. **音符区要服从舞台构图**，该收窄就收窄（本谱 ±440）。
9. **0 特效也能封神**：所有视觉都能用判定线做出来，shader 只是加速器。
10. **成本是真实的**：144 小时、内存告警、掉帧。动画谱要按"做片子"排期。
